## 0. Faz-0 ön-koşullar — BLOKLAYICI (kritikten türetildi)

Adversaryal kritik, tasarımın "bilimsel-bütünlük katmanı mekanik olarak production'a taşınır" iddiasını **mevcut koda karşı** test etti ve 3 diskalifiye edici sorun buldu. Aşağıdakiler herhangi bir Faz-1 işinden **önce** çözülmeli; aksi halde merkezi satış noktası (mekanik dürüstlük) kurgu olur.

1. **Score semantiğini karara bağla (en kritik).** Servis edilen `risk_index` bugün bir **global percentile rank** — yani gate'lenecek lokal baseline karşılaştırması yok ve skor, lokal sismik değişim olmasa bile her refit'te kayar (premium-sürücü değer dengesiz). Karar: skor **absolute-per-cell** (oran/şiddet; lokal recompute + incremental rescore mümkün) **mi**, yoksa **global rank** (tam recompute gerekir; content-hash reproducibility key yeniden tanımlanmalı) **mi**? "Baseline'ı yener" için held-out **spatial skill** metriği tanımla. Bu karar tüm reproducibility + incremental-rescore matematiğini belirler.
2. **`min_mag` tutarlılığı + Mc enforcement.** Mevcut `meta.json min_mag=3.0` ile `build_cell_index` default `4.0` çelişiyor; `run_pipeline.validate_outputs` yanlış invariant'ı doğruluyor ve kendisiyle çelişen yüzeyi geçirirdi. Düzeltme: `meta.min_mag == surface-artifact min_mag == (>= snapshot için hesaplanan Mc)` assert et. Mc/completeness serve+publish'te zorla (`seismology.magnitude_of_completeness` zaten var).
3. **Integrity modülünü inşa et (%0 → çalışır).** `src/eyequake/integrity`: Track-C "rejected" + yasaklı-iddia listesi **enforced sabitler** olarak tek-doğruluk-kaynağı; negation-aware banned-claim linter (CI); runtime Pydantic honesty-envelope validator (provenance/uncertainty/baseline/`tahmini` eksik yanıtı reddeder). Bugün bunlar prose — kod değil.

**Ek bloklayıcılar (production öncesi):**
- **AFAD timezone/magnitude-type/lisans doğrulaması.** Timezone doğrulaması bilinen bir olaya karşı ~1 saatlik iş ama tüm recency/skor zincirini geçersiz kılabilir. Ticari lisans + şema-değişim contract testi + magnitude-type homojenleştirme bloklayıcıdır, ertelenebilir değil.
- **Score=pricing sözleşme kısıtı.** Ürün sözleşmede "**göreli triage / portföy sıralama / accumulation control**" olarak konumlanmalı, **rateable (absolute-loss-kalibre) cat model DEĞİL** — E&O/sorumluluk riski. POSITIONING zaten "göreli risk indeksi 0–100" diyor; bunu API + UI + sözleşmede mekanik olarak zorla.
- **Geocoding doğruluğu = gizli 2. ürün.** TR adres→parsel→hücre hatası skoru sessizce bozar. Etiketli TR adres truth-set'i + ölçülen mis-resolution SLA'li kendi validasyon harness'ı, parsel-seviyesi satıştan önce.
- **Maliyet modeli.** Per-parsel bootstrap CI (n_boot=2000) × yoğunlaştırma × her refit patlayabilir; parsel desteğinde analitik/yaklaşık CI'ya geç.

## 1. Seçilen mimari + gerekçe

**Seçim:** Base on Candidate 1 (FastAPI Modular Monolith) as the deployable skeleton, then graft Candidate 3's precompute-then-serve PostGIS risk surface + integrity-gate-as-pipeline-check + incremental rescore + post-mainshock staleness flag, and Candidate 2's offline model-build, runtime honesty-schema validator, isolated batch worker, and ingestion-robustness layer. Net: a near-monolith (one ASGI app + one batch worker + one scheduler + managed Postgres/PostGIS on Fly.io EU) whose customer-facing layer is a thin, stateless read over a versioned, materialized hazard x site x BIS risk surface, with the existing src/eyequake package imported verbatim as the scoring library and the existing run_pipeline.py honesty/baseline contract promoted into a hard publish gate, a CI gate, AND a runtime response envelope.

**Gerekçe:** Two of three judge lenses (production-readiness, cost/team/TTM) pick Candidate 1 decisively (8, 9) and the third (domain-fit/integrity) only picks Candidate 3 over Candidate 1 by one point (9 vs 8) on two sub-axes — parcel-resolution honesty and data-plane gating — both of which are graftable onto Candidate 1 without changing its operating profile. For a 2-person founding team (Bora=stats, Alp=CS, neither a dedicated SRE) the dominant production risk is on-call burden and bus-factor: an architecture you cannot operate at 3am is not production-ready regardless of elegance. Candidate 1 minimizes standing stateful systems and — verified — reuses src/eyequake (pure numpy/pandas/scipy/sklearn functions, scripts 01-11, run_pipeline.validate_outputs at line 136) with ZERO rewrite, so the code that backtests in evaluate.py is the code that serves (no re-implementation drift, which is itself an integrity requirement). Its module seams (ingestion/scoring/bis/serving/api/billing/integrity) are exactly the lines you would later cut into services, so distribution is deferred until a measured bottleneck forces it. The single decisive graft is Candidate 3's precompute-then-serve: materialize hazard x site scores into GIST-indexed PostGIS tables keyed by (model_version, data_vintage, catalog_snapshot_hash) and serve a thin stateless read path + CDN-cached tiles; this simultaneously raises SLA, makes portfolio batch joins fast, and decouples serving from compute so a pipeline failure degrades to serving slightly-stale (flagged) scores instead of an outage. Candidate 3's full Dagster+AWS+Martin+Nominatim ops surface is correctly judged too heavy for two founders pre-revenue, so I adopt its data-plane DISCIPLINE (asset-checks-as-gates, lineage, incremental rescore) but implement it as the existing run_pipeline gate run on cron/CI rather than standing up Dagster Cloud on day one. Non-negotiable across all three: the verified 0.25 deg grid is NOT parcel resolution — shipping it as a 'parcel score' would itself violate the honesty layer, so grid densification + cadastral parcel geometry + a resolution-confidence flag is a hard precondition before any parcel score is sold, and the schema is shaped (separate fine_grid/parcels/buildings tables, BIS fragility as a thin query-time multiplier) to absorb that densification without rework.

## 2. Kilitlenen tech stack

### Backend
FastAPI + Pydantic v2 on Python 3.11 (Uvicorn behind Gunicorn), single modular-monolith ASGI app exposing both the insurer REST API and the dashboard BFF; src/eyequake imported verbatim as the in-process versioned scoring library (zero rewrite); SQLAlchemy 2.0 + GeoAlchemy2 for typed PostGIS access; Alembic for migrations; hard internal module seams = ingestion / scoring / bis / serving / api / billing / integrity, each extractable to a service later without re-architecture.

### Frontend
Next.js 15 (App Router) + React 19 + TypeScript strict + Tailwind 4 + shadcn/ui insurer dashboard, deployed on Vercel separate from the API; MapLibre GL JS (open, no Mapbox token lock-in, KVKK-friendly self-hosted tiles) + deck.gl for large portfolio overlays; TanStack Query for fetching; every score view renders a MANDATORY uncertainty (bootstrap CI) + provenance (model_version, data_vintage, source=AFAD) + naive-baseline-comparison panel and the explicit 'this is NOT earthquake prediction / deprem tahmini degildir' framing; SSR public methodology/honesty site so disclaimers are first-class.

### Veritabanı
PostgreSQL 16 + PostGIS 3.4, managed (Crunchy Bridge or Supabase) pinned to EU/Frankfurt for KVKK/GDPR residency, with a Turkey-region residency option on the roadmap for Turkish insurer demands. Single source of truth: events (time-partitioned, BRIN), hazard_cells (current 0.25 deg), fine_grid + parcels + buildings (BIS) added during densification, site_layer, and the MATERIALIZED parcel_risk_surface (published vs staging) carrying model_version + data_vintage + catalog_snapshot_hash columns on every scored row; GIST spatial indexes tuned for point-in-polygon and bbox; Row-Level Security for tenant isolation; immutable per-score audit table.

### Geospatial
PostGIS spatial joins for address/parcel -> cell/fine_grid/building resolution and portfolio batch joins (ST_Contains/ST_Intersects/ST_DWithin); vector tiles via Martin (Rust MVT) reading PostGIS for live layers + Tippecanoe -> PMTiles on Cloudflare R2/CDN for the static hazard surface, rendered by MapLibre; geocoding via self-hosted Nominatim/Pelias on an OSM-Turkey extract (Turkish addresses never leave region) with a commercial geocoder as confidence-scored fallback and human-in-the-loop routing for low-confidence matches; TKGM/Tapu-Kadastro cadastral parcel geometry integration on the roadmap (the resolution-densification work that makes 'parcel score' honest). Every score carries a geocode/resolution-confidence flag and a self-reported-vs-official building trust flag.

### Skorlama
Deterministic, versioned scoring core = existing src/eyequake (hazard Track A spatial seismicity-rate field x site Vs30/amplification/liquefaction-screening x BIS building-vulnerability fragility). Heavy recompute runs OFFLINE in the batch worker and is MATERIALIZED into PostGIS (precompute-then-serve), never in the request path -> predictable p99 for synchronous lookups. A score is a deterministic materialization keyed by (catalog_snapshot_hash, grid_params, site_inputs, building_card_version, model_version) so it is byte-identically re-derivable for actuarial/audit validation. Bootstrap CI (evaluate.bootstrap_mean_ci) and baseline_comparison (evaluate.skill_score vs Poisson/mean/persistence) are PRECOMPUTED per cell/parcel and embedded in every response; BIS fragility applied as a thin query-time multiplier on the cached hazard x site surface so the product is sellable on hazard x site before official building data lands. AFAD catalog snapshots stored as content-hashed Parquet on R2; DuckDB for ad-hoc analytical batch.

### Queue/Jobs
Start LOW-OPS: pgmq (Postgres-backed queue) for the batch portfolio-scoring path so there is one fewer managed dependency pre-revenue (Candidate 2's noted fallback); a SINGLE dedicated scheduler process using a Postgres advisory leader-lock for AFAD near-real-time polling (graduating watch_afad.py) and nightly grid/ETAS/site refits — explicitly NOT in-process APScheduler, to avoid double-firing under multiple API replicas. The batch worker runs as a SEPARATE process from day one (failure isolation) so a heavy portfolio job cannot starve the API event loop. Graduate to Redis + ARQ only when hot-score cache / rate-limiting justify it; harden the batch worker with queue-depth autoscaling + dead-letter queue + idempotency keys at extraction time; defer NATS/event-bus until team or scale boundaries actually demand it.

### Infra
Docker + docker-compose for dev; production on Fly.io in EU/Frankfurt (KVKK/GDPR residency, no Kubernetes) running api + batch-worker + scheduler as separate processes plus managed Postgres+PostGIS; Cloudflare R2 for content-hashed Parquet snapshots, PMTiles and portfolio/report exports; Cloudflare in front for CDN/WAF/TLS; light Terraform/Fly config (no premature k8s); reproducible container image stamped per model_version with blue-green-style rollout. Fly.io chosen over AWS ECS/Fargate to cut IAM/YAML ops surface for a 2-person team while keeping the same logical topology.

### Auth
WorkOS for enterprise SSO/SAML + SCIM directory sync on the dashboard (insurers/reinsurers demand it), with Clerk as the faster-to-ship fallback if a pilot does not yet require enterprise SSO; server-side hashed, scoped, rotatable per-tenant API keys for the machine-to-machine insurer API (optional mTLS); multi-tenancy = shared schema + tenant_id + Postgres Row-Level Security enforced in BOTH app and DB so a portfolio join can never cross tenants, schema-per-tenant reserved for large reinsurers; RBAC roles admin / underwriter / analyst / read-only.

### Billing
Stripe Billing — usage-based metered (per parcel scored / per API call / per portfolio row) plus seat/subscription tiers; quota enforcement, overage, invoices and a customer self-serve portal; metering events written TRANSACTIONALLY with each scored request and reconciled against observability usage data for accurate invoicing; per-tenant rate limits and quotas enforced at the API edge (pg/Redis counters).

### Observability

PLUS a dedicated Scientific-Integrity & Drift dashboard reading a model_eval table: AFAD feed lag (live_meta lag_minutes/status), magnitude-of-completeness Mc and Gutenberg-Richter b-value stability, baseline skill_score over time (model vs Poisson/mean/persistence), score-distribution drift, geocode-confidence distribution, and a post-mainshock freshness/staleness flag; any integrity invariant breaking (model stops beating baseline, score missing provenance) auto-flags and pages rather than silently serving. An IMMUTABLE per-score audit log (model_version + AFAD provenance + inputs + tenant + user + timestamp) backs underwriting/regulatory defensibility and KVKK — treated as a day-one requirement.

### CI/CD
GitHub Actions (extending the existing ci.yml): ruff + pytest + run_pipeline.validate_outputs honesty/baseline contract as a HARD deploy gate (source==AFAD, disclaimer contains 'tahmini', required hazard props, ETAS provenance) + a banned-claim linter extending test_web_honesty.py (blocks 'earthquake prediction' / 'deprem tahmini' as a positive claim / 'neural-net prediction' / 'early warning' in any outward copy) + image build to registry + Fly deploy; a runtime Pydantic honesty-schema validator at the API boundary REJECTS any score payload missing model_version / provenance / uncertainty / baseline_comparison / 'tahmini' disclaimer (defense-in-depth: gate at publish AND at response); reproducible image per model_version; blue-green rollout with PITR backups + documented PostGIS restore runbook.

## 5. En üst riskler

- Parcel-granularity vs honesty: the verified 0.25 deg (~25 km) grid is a hazard-zone average, not a parcel score; shipping it as 'parcel-level' before Phase-2 densification + cadastral geometry would itself violate the non-negotiable honesty layer. Mitigation: explicit hazard-zone labeling + geocode-confidence flag in Phase 1; densification + parcel geometry is a hard gate before parcel-level marketing.
- BIS official-data dependency: the stated core differentiator (building-vulnerability) depends on tapu/municipality/urban-renewal data needing access/permits that may be slow or blocked; until then the moat is only self-reported building cards. Mitigation: ship hazard x site from day one, BIS fragility as a thin query-time multiplier with a self-reported trust flag, deepen as official data lands.
- Integrity-vs-sales pressure: a relative descriptive risk index could be oversold as prediction or used to price premiums as a validated cat model (E&O/liability). Mitigation: publish-time baseline gate + runtime honesty-schema validator + CI banned-claim linter that survive product/marketing, and Phase-3 independent validation gating pricing use.
- KVKK/GDPR + residency: insurer portfolios contain addresses (personal data) and EU-reinsurer cross-border flows can collide with Turkish residency duties; wrong-region storage or geocoding abroad is a breach. Mitigation: EU/Frankfurt default + Turkey-region option, self-hosted in-region geocoder, DPA, residency, erasure SLA, immutable access audit.
- Geocoding/parcel-resolution accuracy in Turkey: address->parcel->cell errors silently corrupt underwriting scores. Mitigation: confidence scoring, commercial fallback, human-in-the-loop for low-confidence matches, and a resolution-confidence flag on every score.
- Single-source AFAD dependency: feed outage/format/lag change can break ingestion of the national catalog. Mitigation: USGS FDSN fallback + schema validation on ingest + lag/staleness alerts + content-hashed Parquet snapshots.
- Monolith scaling discipline / precompute freshness: a heavy portfolio batch could starve the API if not isolated, and precompute makes scores stalest right after a mainshock when most demanded. Mitigation: batch worker as a separate process from day one, precompute-then-serve decoupling, incremental rescore + visible post-mainshock staleness flag.
- Team bus-factor/burnout: two founders covering data eng, ML, full SaaS, billing, security and compliance. Mitigation: deliberately low-ops stack (Fly.io, managed Postgres, pgmq before Redis, WorkOS/Stripe/Sentry/Grafana Cloud), defer distribution/Dagster/NATS until measured need, and keep clean seams so help can be added without re-architecture.

## 6. Katman tasarımları (11)

### 6.1 — data-ingestion

Production design for EyeQuake's catalog + near-real-time ingestion layer: the single source of factual ground truth that every downstream score, baseline backtest, and honesty claim depends on. It graduates the verified prototype code (src/eyequake.data.fetch_afad, fetch, clean; analysis.seismology) verbatim into a low-ops service shaped as one batch worker + one leader-locked scheduler over managed Postgres 16 + PostGIS on Fly.io EU. Core principles, all enforced by code not convention: (1) AFAD is the canonical national catalog (clean Gutenberg-Richter b approx 1.0, Mc approx 2.0 for Turkey); USGS FDSN is a fallback/gap-fill source, never silently merged into the science catalog because mixing networks and magnitude types corrupts GR. (2) Every ingested batch is content-hashed and provenance-stamped so a score is byte-identically re-derivable (catalog_snapshot_hash) for actuarial audit. (3) Ingestion cannot publish a catalog that fails seismological sanity (Mc stability, b-value in plausible band, completeness, monotonic time, bbox, magnitude-type homogeneity) - a corrupt feed must degrade to serving the last-good flagged-stale snapshot, never silently corrupt underwriting inputs. (4) The near-live watcher is productionized into a single-writer scheduler with a Postgres advisory leader-lock (no double-fire under multiple API replicas), upserting an events table and emitting a lag/status SLA. (5) AFAD revises magnitudes and retracts false events post-hoc, so ingestion is upsert+version with a nightly reconcile/backfill, and each revision triggers incremental rescore of only affected cells with a visible post-mainshock staleness flag. The honesty layer ('Deprem tahmini degildir' / 'tahmini' in feed meta, source==AFAD) survives into every ingestion artifact and the CI gate.

**Bileşenler:**

- **AFAD Catalog Fetcher (canonical)** — Paged historical + incremental fetch of the AFAD national catalog (apiv2 event/filter) and normalization to the canonical schema. Reuses the verified prototype: yearly paging for backfill, but parameterized to month/week windows on dense periods (e.g. 2023 DAF aftershock sequence) to bound payload size. Emits a raw immutable snapshot before any transform so the exact bytes AFAD returned are auditable. _(src/eyequake.data.fetch_afad.fetch_catalog_afad imported verbatim; requests.Session with retry/backoff (urllib3 Retry); raw JSON -> content-hashed Parquet snapshot on Cloudflare R2; runs in the isolated batch worker process (not the API event loop).)_
- **USGS FDSN Fallback Fetcher** — Secondary catalog source used (a) for cross-validation of AFAD counts, and (b) to gap-fill the near-live feed when AFAD is degraded/stale beyond SLA. Handles FDSN's 204-No-Content (empty window) and the hard 20,000-events-per-window cap by subdividing windows. Tagged source='USGS' and NEVER merged into the GR/hazard science catalog by default - only surfaced as a flagged fallback layer. _(src/eyequake.data.fetch.fetch_catalog returning FetchResult(n_windows, n_failed_windows) for observability; same requests.Session pattern; CSV via pandas.)_
- **Normalizer + Schema Versioning** — Maps each source's raw record (AFAD eventID/date/magnitude/type/location; USGS CSV columns) onto the canonical event contract and stamps provenance (source, source_event_id, schema_version, catalog_snapshot_hash, ingested_at). Validates each record against a strict Pydantic model so an upstream field rename is REJECTED at ingest, not silently coerced. clean_catalog supplies UTC ISO8601 parsing (handles AFAD fractional-second variance), dropna of incomplete rows, and derived year/interevent_days. _(Pydantic v2 CanonicalEvent model; src/eyequake.data.clean.clean_catalog; schema_version column + Alembic-migrated events table; SQLAlchemy 2.0 + GeoAlchemy2 typed writes.)_
- **Dedup + Cross-Source Reconciler** — Two-stage dedup. Stage 1 (existing): within-source dedup by source_event_id. Stage 2 (new): cross-source spatiotemporal matching so the same physical earthquake reported by both AFAD and USGS with different IDs is not double-counted - match on |dt| < 16s AND great-circle dist < 30km AND |dmag| < 0.5, AFAD wins as canonical. Produces a deterministic reconciliation that is identical on re-run (idempotent). _(PostGIS ST_DWithin / great-circle on geography; pandas for in-batch matching; deterministic tie-break (prefer source=AFAD, then larger n_phases if available, then earliest ingested_at).)_
- **Data-Quality Gate Engine** — Hard publish gate run on every candidate canonical snapshot before it becomes the served catalog. Computes Mc (max-curvature +0.2), b-value (Aki MLE + Shi&Bolt sigma), and asserts: b in [0.7,1.3] (Turkey expectation ~1.0; out-of-band signals magnitude-type contamination or corruption), Mc not regressed vs previous snapshot beyond tolerance, monotonic non-future timestamps, all coords inside TURKEY bbox and not null-island, magnitude-type homogeneity (no mixed ML/Mw feeding one b-value), and event-count delta within sane bounds vs prior. Failure BLOCKS publish and pages; the prior good snapshot keeps serving (flagged). _(src/eyequake.analysis.seismology.magnitude_of_completeness + b_value_aki imported verbatim; results written to a data_quality_gate row; wired into scripts/run_pipeline.py as a gate alongside the existing validate_outputs honesty check; failing gate => non-zero exit in CI.)_
- **Near-Live Watcher (productionized)** — Graduates watch_afad.py from an in-process while-loop writing flat geojson into a single-writer poller that upserts the events table and emits the feed SLA (status fresh/stale/empty, lag_minutes, latest_event_time, checked_at). Polls a short AFAD lookback window, dedups by eventID, and on any new M>=threshold event enqueues an incremental-rescore job. Separates the UX micro-event live layer (min_mag 0.0) from the canonical science catalog (min_mag 2.5) so micro events never pollute completeness/GR. _(scripts/watch_afad.py logic refactored to write Postgres + live_meta; runs inside the single scheduler process under a Postgres advisory leader-lock; enqueues to pgmq; structlog JSON + OpenTelemetry spans.)_
- **Scheduler / Orchestrator (single, leader-locked)** — One dedicated process (NOT in-process APScheduler per API replica) that owns all cadenced ingestion: near-live AFAD poll (e.g. 60s), nightly full reconcile/backfill, and the daily quality-gate + snapshot publish. A Postgres advisory leader-lock guarantees exactly one active scheduler even if the process is replicated, so polls and refits never double-fire. _(Single Fly.io machine running APScheduler bounded by pg_advisory_lock; jobs dispatch real work to the batch worker via pgmq; health-pinged by Better Stack.)_
- **Backfill / Reconciliation Job** — Periodic full re-fetch of the historical window AFAD is known to revise (lookback configurable) to capture (a) post-hoc magnitude revisions, (b) retractions of false events, and (c) late-arriving events. Diffs the fresh snapshot against canonical: upserts revised rows (new version), tombstones retracted rows, inserts new ones, and emits the set of affected cells for incremental rescore. Compares snapshot content-hashes to short-circuit no-op nights. _(Batch worker (pgmq-driven), idempotent upsert by (source, source_event_id) + version; content-hashed Parquet snapshot comparison on R2; DuckDB for fast analytical diffing of large snapshots.)_
- **Ingestion Persistence (events + snapshots)** — System of record for all ingested seismicity. Time-partitioned events table (PostGIS geometry, BRIN on time, GIST on geom) holding canonical + fallback + tombstoned rows with full provenance; an immutable catalog_snapshot registry (one row per content-hashed snapshot) that is the reproducibility anchor for every downstream materialized score; raw source payloads archived to R2. _(PostgreSQL 16 + PostGIS 3.4 (managed, EU/Frankfurt); SQLAlchemy 2.0 + GeoAlchemy2; Alembic migrations; Cloudflare R2 for content-hashed Parquet + raw JSON/CSV archives.)_
- **Ingestion Observability + Staleness SLA** — Surfaces the integrity-critical ingestion signals: AFAD feed lag_minutes/status, ingest counts per source, dedup/cross-source-match ratio, Mc and b-value stability over time, source-mix, and gate pass/fail. Pages when the feed exceeds the staleness SLA or a quality gate breaks. Fixes the observed config drift (watch_afad default stale_after_minutes=30 but live_meta written with 5) by making the SLA threshold a single configured value surfaced in meta. _(OpenTelemetry -> Grafana Cloud (Prometheus metrics, Loki logs) + Sentry (errors); the Scientific-Integrity & Drift dashboard reads model_eval/data_quality_gate tables; Better Stack uptime; feed status mirrored to a public /v1/feed/status endpoint.)_

**Veri akışı:** Backfill path (cold start + nightly): Scheduler (leader-locked) dispatches a fetch job to the batch worker -> AFAD Catalog Fetcher pages the apiv2 event/filter endpoint by year (subdividing to month/week on dense sequences) -> raw JSON is content-hashed and archived to R2 BEFORE transform -> Normalizer validates each record against the CanonicalEvent Pydantic model and maps to canonical schema -> clean_catalog parses UTC ISO8601, drops incomplete rows, derives year/interevent_days -> Dedup Reconciler removes within-source duplicates (by source_event_id) and cross-source duplicates (spatiotemporal match vs any USGS rows) -> the candidate snapshot enters the Data-Quality Gate Engine which computes Mc and b-value and asserts the seismological sanity invariants -> on PASS the snapshot is registered in catalog_snapshot with its catalog_snapshot_hash and the events table is upserted (revisions versioned, retractions tombstoned); on FAIL nothing is published, the prior good snapshot stays canonical, and an alert pages. A published snapshot emits the set of affected cells to pgmq for downstream incremental rescore (consumed by the scoring layer, out of scope here).\n\nNear-live path: the same Scheduler process runs the Near-Live Watcher under the advisory leader-lock every interval -> queries a short AFAD lookback window (min_mag 0.0 for the UX live layer) -> dedups by eventID -> computes feed SLA (status fresh/stale/empty, lag_minutes from latest_event_time vs checked_at) -> upserts new M>=2.5 events into the canonical events table and writes the live_events + live_meta artifacts -> any new significant event enqueues an incremental-rescore job and, if it is a mainshock, sets a post-mainshock staleness flag that is visible in the API/UI until the affected cells are rescored. If AFAD is unreachable or stale beyond SLA, the watcher fails over to the USGS FDSN Fallback Fetcher, marks the feed degraded, and keeps the lag clock running so the staleness is honestly surfaced rather than hidden. Every artifact (events rows, snapshots, live_meta) carries source provenance and the 'Deprem tahmini degildir' / 'tahmini' disclaimer, and the CI honesty gate (run_pipeline.validate_outputs + banned-claim linter) blocks any build whose ingestion artifacts drop source==AFAD or the disclaimer.

**Failure mode'lar:**

- _EMPTY: AFAD returns an empty array for the live window (no events recently)._ → Treat as status='empty', not an error. Keep the last-good events; do not zero out the catalog. lag_minutes keeps climbing off latest_event_time; if it crosses stale_after_minutes -> status='stale' and page. Distinguishes 'quiet seismicity' from 'feed down' by also checking AFAD HTTP health.
- _ERROR: AFAD HTTP 5xx / 429 / timeout / connection refused._ → urllib3 Retry with exponential backoff (max 4). On exhaustion: for live path fail over to USGS FDSN fallback and set status='degraded' + fallback_source='USGS'; for backfill record the window in windows_failed and retry it in the next run rather than publishing a partial snapshot as complete. Sentry alert; never corrupt canonical.
- _SCHEMA CHANGE: AFAD renames/removes a field or returns a non-list payload._ → Pydantic validation rejects the batch (existing watch_afad already guards non-list payloads). The candidate snapshot is discarded, the prior good snapshot keeps serving, and a contract-break alert pages. A pinned fixture in contract tests turns the same break into a red CI before it reaches prod.
- _PARTIAL: some yearly/monthly backfill windows fail while others succeed._ → fetch.py already returns n_failed_windows; the snapshot is marked incomplete and NOT published as canonical. Failed windows are re-queued. A gap-flag is recorded so downstream never assumes completeness over an unfetched interval. Quality gate's count-delta check would also trip on a large unexplained drop.
- _FDSN 20,000-event window cap hit (dense period / wide window)._ → fetch._fetch_window raises RuntimeError; the fetcher subdivides the window (year->month->week) and retries until each sub-window is under the cap. Idempotent because dedup collapses any overlap at window boundaries.
- _DOMAIN: magnitude revision - AFAD updates the magnitude of an existing eventID days later._ → Upsert by (source, source_event_id) creates a new version row (old kept for audit). Reconcile job detects the delta, enqueues incremental rescore of affected cells, and stamps a new catalog_snapshot_hash so prior scores remain reproducible against their original snapshot.
- _DOMAIN: event retraction - AFAD removes a previously reported false/duplicate event._ → Nightly full reconcile diffs fresh snapshot vs canonical; an event absent from the fresh full window is soft-deleted (is_tombstoned=true, kept for audit, excluded from served view) and affected cells are rescored. Requires confirming AFAD retraction semantics (open question).
- _INTEGRITY: b-value falls outside [0.7,1.3] or Mc jumps between snapshots._ → Data-Quality Gate marks status='fail', blocks publish, and pages. Out-of-band b almost always means magnitude-type contamination (ML mixed with Mw), a truncated catalog, or upstream corruption - exactly the conditions under which a score must NOT be sold. The last good snapshot keeps serving, flagged.
- _DOMAIN: mainshock burst (Feb-6-2023-style aftershock sequence, thousands of events in minutes)._ → Window subdivision bounds payload size; batch upsert with COPY for throughput; pgmq rescore queue absorbs the spike with queue-depth monitoring + DLQ + idempotency keys. A post-mainshock staleness flag is set and surfaced honestly until incremental rescore catches up - the worst-case freshness moment is monitored, not hidden.
- _DOMAIN: timezone / clock anomalies - AFAD time semantics shift, or a future-dated or epoch-zero event appears._ → clean.py parses UTC ISO8601 (already handles AFAD fractional-second variance via format='ISO8601'); validators reject time>now+5min and null-island coords. A diurnal-distribution sanity check flags a sudden ~3h shift that would indicate a local-time-vs-UTC regression (the assumed-UTC mapping is an open question).
- _OPS: scheduler double-fire under multiple replicas, or duplicate live records within one poll._ → Postgres advisory leader-lock ensures exactly one active scheduler. Within a poll, dedup-by-eventID (existing) plus the unique (source, source_event_id, version) constraint make upserts idempotent, so a retried poll cannot create duplicate events.
- _OPS: R2 snapshot write fails after DB upsert (or vice versa)._ → DB is authoritative for the served catalog; R2 archive write is retried and reconciled by the next run (snapshot row records r2 URIs and a write-confirmed flag). The catalog_snapshot is only marked is_published after both the gate passes and the archive is confirmed, so an unverifiable snapshot never becomes canonical.

Honesty over coverage.

### 6.2 — scoring-engine

Deterministic, versioned, reproducible parcel-risk scoring engine that composes hazard (Track A relative seismicity-rate index) x site amplification (Vs30/liquefaction) x building vulnerability (BIS fragility) into a 0-100 parcel risk index, where EVERY emitted score carries a bootstrap uncertainty band, full provenance, and an attached naive-baseline comparison, and is byte-identically re-derivable from a content-hash key. The engine reuses src/eyequake VERBATIM as the in-process scoring library (build_cell_index, amplification, slope_to_vs30, liquefaction, bootstrap_mean_ci, skill_score, magnitude_of_completeness/b_value_aki) so the code that backtests in evaluate.py is the code that serves -- no research-vs-production drift. Architecture is two-stage: Stage 1 (offline batch) materializes a RE-RANKED hazard x site surface into GIST-indexed PostGIS keyed by (catalog_snapshot_hash, model_version); Stage 2 (query-time) applies the per-request BIS building card as a BOUNDED, saturation-safe headroom adjustment (a building shifts a parcel within its hazard envelope, it cannot fabricate hazard). VERIFIED-EXISTING primitives are reused unchanged; this layer NEWLY specifies (a) the parcel-v1 composition formula that replaces the saturating multiplicative clamp in site_adjusted_risk with a re-rank + headroom transform, (b) the model/version registry with a hard publish gate (a version goes live only if it beats Poisson/persistence on a rolling out-of-time holdout AND passes the Mc/b-value completeness gate), and (c) a runtime Pydantic honesty-schema that REJECTS any score payload missing model_version / catalog_snapshot_hash / uncertainty / baseline_comparison / resolution flag / 'tahmini' disclaimer. Non-negotiable: the 0.25deg (~25km) grid is hazard-zone resolution, explicitly labeled as such and NOT sold as a true parcel score until Phase-2 densification; the index is descriptive/relative, never a date-place-magnitude prediction.

**Bileşenler:**

- **ScoreComposer (parcel-v1)** — Single source of truth for the composition formula: pure deterministic function combining hazard_zone_index x site (amp/liquefaction) x BIS fragility -> 0-100 parcel risk + propagated CI. Identical code runs in the batch materializer AND the request path (zero re-implementation). Stage-1 (re-rank hazard x site) and Stage-2 (bounded headroom BIS) transforms live here. _(New module src/eyequake/scoring/parcel.py (numpy/pandas, Python 3.11), imported verbatim by FastAPI app and batch worker; wraps existing analysis/hazard.build_cell_index, analysis/site.amplification|slope_to_vs30|liquefaction)_
- **HazardSiteMaterializer (Stage 1)** — Offline batch job that runs build_cell_index + site layer over the pinned AFAD snapshot, folds site amplification + liquefaction screening into raw_site, RE-PERCENTILES across the parcel/cell population to a saturation-free site_hazard_index, and writes the materialized surface to PostGIS keyed by (catalog_snapshot_hash, model_version). Never runs in the request path -> flat p99. _(Batch-worker process (separate from API, Fly.io EU), SQLAlchemy 2.0 + GeoAlchemy2 -> PostgreSQL 16/PostGIS 3.4; reads content-hashed Parquet snapshot from Cloudflare R2; scripts 04/06/10 graduated)_
- **UncertaintyEstimator** — Computes the mandatory bootstrap CI per cell via block-resampling of the catalog/windows (evaluate.bootstrap_mean_ci), maps the rate band through the Stage-1 transform to a band on the index, and applies epistemic widening for inferred-Vs30 and self-reported-BIS. Band is precomputed on the surface and propagated through Stage-2 at query time. _(src/eyequake/forecast/evaluate.bootstrap_mean_ci (n_boot=2000, alpha=0.05, seed=0) in the batch worker; CI columns stored on site_hazard_cells in PostGIS)_
- **BaselineComparator** — Per-region, precomputes skill_score of the hazard model vs climatology(Poisson) and persistence on an out-of-time holdout (temporal_split + poisson_deviance) and sets beats_baseline. Writes model_eval rows; result is embedded in every score and is the data feeding both the publish gate and the Phase-3 drift dashboard. _(src/eyequake/forecast/{baselines.climatology_forecast|persistence_forecast, evaluate.temporal_split|score|skill_score}; results in PostgreSQL model_eval table)_
- **BISFragilityResolver** — Maps a building card (age / floors / structure type) to a fragility_class -> bounded multiplier m_bis and a trust flag (self_reported | official | unknown). Defaults to neutral m_bis=1.0 when no card is present so the product is sellable on hazard x site from day one; deepens as official tapu/municipality data lands. _(Pydantic v2 BuildingCard model + versioned fragility_lookup table in PostgreSQL; resolver in src/eyequake/scoring/bis.py, applied query-time)_
- **ModelVersionRegistry + PublishGate** — Registry of every hazard/site/parcel/engine-constants artifact with status staging|published|deprecated, params, git_sha, catalog_snapshot_hash and eval_report. PublishGate promotes staging->published ONLY if eval_report shows beats_baseline=true on the rolling holdout AND Mc/b-value within stability bounds AND honesty-schema valid. Promotes run_pipeline's contract into a hard gate. _(PostgreSQL model_version table + Alembic migrations; artifacts (Parquet/model params) on R2; gate implemented as run_pipeline.validate_outputs extension on GitHub Actions CI + nightly cron (NOT Dagster))_
- **CompletenessGate (Mc / b-value)** — Refuses to publish or score any region whose catalog is below magnitude-of-completeness or whose Gutenberg-Richter b-value is unstable -- below Mc a score models reporting bias, not seismicity. Hard precondition on Stage-1 materialization. _(src/eyequake/analysis/seismology.magnitude_of_completeness | b_value_aki, invoked by PublishGate in the batch worker)_
- **ScoreEnvelopeBuilder + HonestySchema** — Assembles the final ScoreEnvelope (point value, uncertainty band, components, baseline_comparison, provenance, flags, disclaimer) and runs the runtime validator that REJECTS any payload missing model_version / catalog_snapshot_hash / uncertainty / baseline_comparison / resolution flag / 'tahmini' disclaimer. Defense-in-depth alongside the publish-time gate and CI banned-claim linter. _(Pydantic v2 strict models at the FastAPI boundary; banned-claim linter extending tests/test_web_honesty.py)_
- **ReproKey + AuditWriter** — Computes the content-hash score_id = sha256(catalog_snapshot_hash | grid_params | site_inputs | building_card_version | model_version | parcel_ref | engine_constants) and writes one append-only audit row per emitted score for actuarial/regulatory re-derivation and KVKK defensibility. _(Python hashlib in ScoreComposer; immutable score_audit_log table in PostgreSQL 16 with RLS, append-only (no UPDATE/DELETE grants))_

**Veri akışı:** OFFLINE (batch worker, scheduled by the single leader-locked scheduler): AFAD national catalog snapshot is content-hashed and stored as Parquet on R2 -> CompletenessGate computes Mc/b-value per region and aborts publish for incomplete sub-catalogs -> HazardSiteMaterializer runs build_cell_index (6-signal relative index) and the site layer (slope->Vs30->amplification, liquefaction screening), folds site into raw_site = H_hazard * (amp/AMP_REF) * (1 + K_LIQ*liq_score), RE-PERCENTILES to a saturation-free site_hazard_index -> UncertaintyEstimator attaches bootstrap CI band -> BaselineComparator attaches per-region skill_vs_poisson / skill_vs_persistence + beats_baseline -> all written to a STAGING site_hazard_cells surface in PostGIS keyed by (catalog_snapshot_hash, model_version) -> PublishGate validates (beats baseline AND Mc-stable AND honesty-schema) and flips staging->published in ModelVersionRegistry; a pipeline failure leaves the prior published surface serving (flagged slightly stale), never an outage. ONLINE (stateless read, request path): address|lat/lon -> geospatial layer resolves to fine_grid/parcel + geocode_confidence (out of this layer's scope, consumed as input) -> single GIST point-in-polygon read of the PUBLISHED site_hazard_index + CI + baseline_comparison for that cell at the pinned model_version -> BISFragilityResolver turns the request building card into m_bis + trust flag -> ScoreComposer Stage-2 applies the bounded headroom BIS adjustment and propagates the CI (widening for inferred Vs30 / self-reported BIS) -> ScoreEnvelopeBuilder assembles the envelope -> HonestySchema validates or REJECTS -> ReproKey/AuditWriter records score_id + provenance + envelope append-only -> response. INCREMENTAL: a new AFAD mainshock triggers rescore of only the event-affected cells and sets post_mainshock_stale=true on the rest until the next full refit, surfaced in every envelope.

**Contract'lar:**

- `parcel-v1 composition formula (the score contract)` — Constants (versioned in engine_constants, hashed into score_id): AMP_REF=1.15, K_LIQ=0.25, w_up=0.50, w_dn=0.50. STAGE 1 (offline, per cell): H_hazard = build_cell_index(...).risk_index in [0,100] (descriptive percentile rank, NOT probability); amp = amplification(slope_to_vs30(slope)) in [0.8,3.0]; m_site = amp/AMP_REF in [0.70,2.61]; m_liq = 1 + K_LIQ*liq_score in [1.00,1.25] (bounded screening surcharge, liquefaction is a proxy not geotechnical); raw_site = H_hazard*m_site*m_liq; site_hazard_index S = 100*percentile_rank(raw_site over population) -> 0..100, saturation-free. Properties: bounded [0,100]; monotonic non-decreasing in amp, liq_score, m_bis; m_bis=1 & amp=AMP_REF -> identity; never saturates whole population. **Failure mode'lar:**

- _Empty cell: no events >= min_mag in the parcel's cell (build_cell_index only emits non-empty cells, so no row exists)._ → Return 200 with parcel_risk=null, flags=['insufficient_seismic_history'], plus a nearest-populated-cell value explicitly flagged 'neighbor_fallback'. Never fabricate a rate from zero events; never silently impute 0.
- _Catalog below Mc / unstable b-value for a region at refit time._ → CompletenessGate blocks PublishGate for that region; the prior published surface keeps serving with post_mainshock/stale flags; never publish a surface that models reporting bias rather than seismicity. Alert fires on the integrity dashboard.
- _Model stops beating Poisson/persistence on the rolling holdout (beats_baseline=false)._ → Publish blocked; if a live region loses skill, its scores are emitted with flags=['no_skill_over_baseline'] and the envelope's beats_baseline=false, and the drift monitor pages. A no-skill score may not be marketed as skillful (CI banned-claim linter).
- _Site data unavailable: elevation/open-meteo source down so Vs30 cannot be derived._ → Fall back to neutral amp=1.0 (NOT rock), set flags=['site_resolution_unavailable'], widen the CI by the site epistemic factor, and echo it in provenance. Never silently treat missing site as favorable.
- _BIS unknown or self-reported building card._ → Unknown -> m_bis=1.0, trust='unknown'; self_reported -> apply m_bis but trust='self_reported', widen CI, and (E&O policy) allow downward credit only with trust='official'. Surface the trust flag on every score so underwriters see the data quality.
- _Post-mainshock staleness: precomputed scores are stalest right after a mainshock, exactly when demand spikes._ → New AFAD event triggers incremental rescore of affected cells; all other cells carry post_mainshock_stale=true and a widened CI until the next full refit. Staleness is an explicit, monitored envelope field, never a hidden SLA miss.
- _Saturation: multipliers would pin the whole population to 100 and destroy discrimination at the top of the market._ → Stage-1 re-percentile keeps site_hazard_index uniformly distributed; Stage-2 bounded headroom transform mathematically cannot exceed 100 or invert ordering. Property tests assert no saturation and monotonicity.
- _Naked/non-compliant payload: a code path tries to emit a score missing model_version, catalog_snapshot_hash, CI, baseline_comparison, resolution flag, or the 'tahmini' disclaimer._ → Runtime HonestySchema (Pydantic v2 strict) REJECTS with a contract error before the response leaves the boundary; CI banned-claim linter blocks any outward copy containing 'earthquake prediction'/'deprem tahmini' as a positive claim/'neural-net prediction'/'early warning'.
- _Non-reproducible score: re-deriving from the score_id key yields a different value._ → Determinism golden test + a periodic re-derivation audit job recompute from score_id inputs and assert byte-identical equality; mismatch is a hard audit failure that pages. Engine constants are hashed into the key so an unversioned constant change cannot silently alter scores.
- _Degenerate numerics: catalog_years=0 (single-snapshot), single-event cell, NaN/inf rate._ → Guard at ingest (require date span > 0) and in ScoreComposer (reject NaN/inf -> CompositionError -> 500); single-event cells flagged 'wide_uncertainty' with maximally widened CI.
- _Version skew: a portfolio batch spans an AFAD refit / model_version change mid-run._ → Each row is scored and stamped with the model_version resolved at job start (pinned), echoed per row; the batch result header reports the pinned (model_version, catalog_snapshot_hash) so an actuarial join is never silently mixed across versions.
- _Low geocode confidence: address->parcel resolution is uncertain (input from geospatial layer)._ → resolution_confidence echoed in provenance; below a configured threshold the score carries flags=['low_geocode_confidence'] and is routed to human-in-the-loop; never silently assign a parcel and present full precision.

**Tasarım kararları:**

- **How to combine hazard x site x BIS without saturating the 0-100 index:** Two-stage: Stage-1 offline RE-PERCENTILE of (hazard x site) into a saturation-free site_hazard_index, then Stage-2 query-time BOUNDED HEADROOM adjustment for BIS (parcel_risk = S + (100-S)*w_up*(m_bis-1) upward / S*(1-w_dn*(1-m_bis)) downward), replacing the existing saturating multiplicative clamp in site_adjusted_risk. — BIS arrives per-request from a building card and cannot be pre-ranked, so it must be a query-time multiplier (per locked stack); a naive multiply on a 0-100 index with factors up to ~5.8x pins everything to 100 and destroys discrimination exactly at the high-risk parcels insurers price. Headroom transform is bounded, monotonic, saturation-safe, and semantically honest: a building shifts a parcel WITHIN its hazard envelope, it cannot manufacture hazard.
- **Where the scoring formula lives:** Import src/eyequake VERBATIM as an in-process library; the new parcel-v1 composition is a thin module (scoring/parcel.py) over the existing verified primitives, run identically in the batch worker and the request path. — The code that backtests in evaluate.py must be the code that serves -- eliminating research-vs-production drift is itself a scientific-integrity requirement and the cheapest path for a 2-person team (zero rewrite, already CI-tested).
- **What semantic the customer-facing number carries:** Keep it a RELATIVE descriptive percentile index (0-100 = where this parcel ranks in Turkey), never an absolute probability; always emit it with an attached bootstrap CI band and a baseline comparison so it is never a naked point estimate. — build_cell_index is verifiably a percentile rank, not a probability; presenting it as probability/prediction would violate the banned-claim layer. CI + baseline make the honest epistemic status legible at the point of use.
- **Uncertainty primitive:** Block-bootstrap CI (evaluate.bootstrap_mean_ci, n_boot=2000, alpha=0.05, seed=0) on the per-cell rate, mapped through the composition transform, with fixed epistemic widening factors for inferred-Vs30 and self-reported-BIS. — Already implemented, already validated, and explicitly designed to quantify single-split noise; a deterministic seed keeps the band reproducible for audit.
- **Reproducibility key:** Content-hash score_id = sha256(catalog_snapshot_hash | grid_params | site_inputs | building_card_version | model_version | parcel_ref | engine_constants) plus an append-only audit log, instead of relying on data_vintage columns alone. — Actuarial/regulatory validation requires byte-identical re-derivation; hashing engine constants into the key makes an unversioned constant change impossible to slip through silently.
- **Integrity gate placement:** Defense-in-depth: publish-time gate (beats Poisson/persistence on rolling out-of-time holdout AND Mc/b-value stable) implemented as the run_pipeline contract on CI/cron, PLUS a runtime Pydantic honesty-schema that rejects non-compliant payloads, PLUS a CI banned-claim linter. — A single gate is a single point of failure against sales/marketing pressure; gating at publish, at response, and at copy makes the honesty layer survive the org, not just the code. Implementing the asset-check CONCEPT via run_pipeline avoids standing up Dagster for two founders.
- **Liquefaction handling in the formula:** Apply as a small bounded surcharge multiplier (m_liq = 1 + 0.25*liq_score, capped at 1.25) with an explicit screening caveat and liq_class flag, NOT folded silently into a single number. — Liquefaction here is a screening proxy (no borehole/groundwater data); it must inform but never dominate or masquerade as a geotechnical assessment.
- **Behavior when BIS data is absent:** Default to neutral m_bis=1.0 with trust='unknown'; allow downward (resilience credit) adjustment only with trust='official'. — Lets the product ship on hazard x site from day one and deepen as official tapu data lands; crediting resilience on self-reported data is an E&O/liability risk, so verified data is required to lower a premium-driving score.
- **Resolution honesty for the 0.25deg grid:** Label every Phase-1 score resolution='hazard_zone' with flags=['resolution_is_hazard_zone_not_parcel'] and a geocode_confidence; true cadastral 'parcel' resolution is gated on Phase-2 densification. — The verified ~25km grid is a hazard-zone average; selling it as 'parcel-level' before densification would itself be a false-precision integrity violation.

**Test:** Determinism / reproducibility golden test: a fixed pinned input set (catalog_snapshot_hash + grid_params + site_inputs + building_card_version + model_version) produces a byte-identical score_id AND parcel_risk across runs and across batch-vs-request paths.; **Açık sorular:**

- Fragility taxonomy + calibration: which standard underpins m_bis -- EMS-98 vulnerability classes, HAZUS/RISK-UE building types, or Turkish TBDY-2018 classes -- and can m_bis and w_up/w_dn be empirically calibrated against 2023 DAF (Feb 6) damage data rather than expert-judgment defaults?

### 6.3 — bis-building-vulnerability

The building-vulnerability layer is EyeQuake's core differentiator: it turns a user-input building card (structure type, construction era/age, floors, soft-story, irregularity, retrofit) into a relative, descriptive vulnerability class (EMS-98-style A..F) and a bounded multiplier applied at query time on top of the existing hazard×site surface (the materialized output of site.py's site_adjusted_risk). It is NOT a damage/collapse prediction and NOT a trained ML model — there is no labeled fragility ground-truth for Turkey, so the model is an expert-elicited taxonomy (EMS-98 × TBDY code generations × structure type), transparent and auditable, with outcome-validation against 2023 Kahramanmaraş damage data deferred and gated. Missing or low-confidence building data degrades gracefully via statistical credibility shrinkage (κ) back to the honest site-only score, always flagged — never an invented optimistic number. Self-reported cards carry a trust flag and an anti-gaming downward cap so a policyholder cannot cheaply lower a premium. Storage is append-only, versioned, tenant-RLS PostGIS (building_card_version feeds the content-hash reproducibility key). Official tapu/municipality/Kentsel-Dönüşüm data lands later into a separate buildings table with lineage and a trust hierarchy that supersedes but never deletes self-reported cards. The whole layer reuses site.py's bounded-bin pattern and plugs into the locked FastAPI + PostGIS + Pydantic-honesty-validator stack.

**Bileşenler:**

- **building card validation models** — Pydantic v2 BuildingCardIn (enums for structure_type/era/source/trust, numeric ranges for year_built/n_floors, booleans for soft_story/irregularity/amnesty/retrofit, cross-field validators: retrofit_year>=year_built, year_built<=current year, masonry+high-floors plausibility flag) and BuildingCardOut (echoes class/multiplier/confidence/provenance). - **building API router (/v1/buildings)** — CRUD-as-append for cards: POST /card (create/version), GET /{building_id} (latest + fragility + provenance), GET /{building_id}/history, and the inline-card path inside /v1/score. **Failure mode'lar:**

- _EMPTY: no building card resolves for the parcel_ → kappa=0 -> M_eff=1.0 -> parcel_risk = site_risk exactly; building.applied=false, resolution='site_only', reason='no_card'. - _ERROR: malformed card (bad enum, year_built=2300, n_floors=-1, retrofit_year<year_built)_ → Pydantic v2 rejects at the API boundary -> HTTP 422 with per-field error list; nothing written; no partial state. - _PARTIAL: card has structure_type but missing floors/soft_story/era, or structure_type=unknown_ → Compute V on provided fields, impute missing high-weight fields with conservative era-cohort means (never optimistic), lower completeness -> lower kappa -> M_eff shrinks toward 1.0 (credibility weighting). resolution='building_partial'; imputed fields listed in response. Low information regresses to the honest site-only score rather than overclaim.
- _SUCCESS: complete, surveyed/official card_ → kappa ~0.85-1.0 -> full multiplier applied, resolution='building_full', retrofit credit uncapped; response carries vulnerability_class, multiplier_raw vs effective, trust_flag, full provenance + uncertainty + baseline. parcel_risk reflects building physics on top of hazard×site.
- _GAMING: self-reported retrofit / favorable structure to lower premium_ → retrofit_trust=0.2 for self_reported (caps credit at ~-0.05 of V), AND downward gaming cap floors M_eff at 0.90 for self_reported -> a self-report can never cut the score >10%. Full reduction requires trust in {surveyed,official} with evidence_ref. Worse-than-baseline self-reports ARE applied (conservative direction trusted). Explicit, audited moral-hazard control.
- _GEOCODE MISMATCH: card point far from declared parcel, or low geocode_confidence_ → If geocode_confidence below threshold or card-to-parcel distance > tolerance -> route to human-in-the-loop queue, do NOT auto-apply overlay; serve site_only with reason='geocode_low_confidence'. geocode_confidence surfaced on every score so underwriters see resolution quality.
- _CONFLICT: official data contradicts an existing self-reported card_ → Reconciliation records both in building_card_conflicts, scoring uses official (higher precedence), self-reported card retained (KVKK audit + dispute trail). Tenant notified of the override. No silent overwrite; lineage shows which source drove the score.
- _STALE: card predates a damaging earthquake or a retrofit done after capture_ → Card carries valid_from; the post-mainshock staleness flag (from incremental-rescore) propagates to building-informed scores in the affected area: response flags 'bina karti olay oncesi' and prompts re-survey. prior_unrepaired_damage / retrofit set via a new card_version; old version preserved.
- _IMPLAUSIBLE COMBO: 15-floor unreinforced_masonry, or steel high-rise pre-1975_ → Not auto-rejected (rare-but-real), but flagged plausibility_warning; masonry>3 floors triggers the +0.10 penalty branch (physically conservative). Surfaced for underwriter review; logged for taxonomy-quality monitoring.

**Tasarım kararları:**

- **How to derive building vulnerability:** Expert-elicited ordinal taxonomy (EMS-98 × TBDY code-generation × structure type) -> class -> bounded multiplier, NOT a trained ML/DL model — No labeled fragility ground-truth for Turkey yet; a trained model would manufacture false statistical authority and violate the integrity layer (and the documented no-fake-DL stance). The taxonomy is transparent, auditable, actuary-defensible, and mirrors site.py's bounded-bin pattern. Outcome-validation vs 2023 damage data is a future, gated upgrade.
- **How building data combines with the existing surface:** Bounded query-time multiplier on the materialized hazard×site surface, never baked into the precompute — Matches the locked stack ('BIS fragility as a thin query-time multiplier'); keeps hazard×site sellable from day one; lets a building card be a per-request overlay; preserves the precompute-then-serve SLA primitive (the heavy surface stays building-agnostic and cache-friendly).
- **How to handle missing/partial building data:** Statistical credibility shrinkage kappa that pulls M_eff toward 1.0 (back to site-only) as confidence drops — Unifies 'missing' (kappa=0) and 'partial' (kappa between) into one principled rule instead of ad-hoc branches; statistician-founder-defensible credibility weighting; guarantees low-information inputs regress to the honest baseline rather than overclaim. Missing building is never an invented low-risk number.
- **Trust handling for self-reported vs surveyed vs official:** Trust hierarchy feeding source_trust into kappa, plus a downward-adjustment cap (self-report can't cut score >10%, retrofit credit x0.2) — Insurance has a moral hazard: an input card can be biased toward a cheaper premium. Conservative (worse) self-reports are trusted; favorable ones require surveyed/official evidence. Explicit, audited anti-gaming control rather than blind trust.
- **Card storage model:** Append-only, versioned, tenant-RLS PostGIS table; corrections are new versions, never in-place edits — building_card_version is part of the content-hash reproducibility key (byte-identical re-derivation for actuarial/regulatory audit); KVKK and underwriting defensibility require an immutable trail; valid_from supports the post-mainshock staleness flag.
- **Official data integration timing and shape:** Separate buildings table with lineage + license, ingested later by the batch worker, superseding but never deleting self-reported cards — Official tapu/municipality/Kentsel-Donusum data is access/permit-blocked, so it cannot gate launch; the schema absorbs it without rework. A separate table with provenance preserves the dispute trail and lets the trust hierarchy resolve conflicts transparently. Deepens the differentiator competitors lack as access lands.
- **Outward framing of the building score:** Relative descriptive vulnerability CLASS (A..F) with mandatory 'not a damage/collapse prediction, not RBTE' adjacency + CI banned-claim linter — A building multiplier could be oversold as 'this building will collapse' (E&O/liability + integrity violation). Framing it as relative/descriptive, never absolute damage probability, and enforcing it in code (response validator + linter) keeps the honesty layer surviving product/marketing pressure.

### 6.4 — geospatial-serving

The geospatial-serving layer turns an insurer's address or lat/lon (single lookup or a CSV of thousands of parcels) into a versioned, honesty-wrapped risk score by: geocoding in-region with a confidence score, resolving the point to a spatial unit via PostGIS, reading a PRECOMPUTED materialized risk surface (never computing in the request path), and emitting a mandatory envelope (uncertainty + naive-baseline comparison + AFAD provenance + resolution-honesty flags + 'deprem tahmini DEGILDIR' disclaimer). The single hardest constraint is resolution honesty: the verified production grid is cell_deg=0.25 deg (~25 km hazard-zone average, from build_cell_index), NOT a parcel. The layer therefore labels every Phase-1 score as level=hazard_zone, attaches geocode_confidence + resolution_confidence + building_trust, and structurally refuses to emit level=parcel until densification (fine_grid -> cadastral parcels) lands. The authoritative point->cell math is the SAME two lines used by build_cell_index (export.py:36-37), promoted to one shared function so the score that backtests in evaluate.py is byte-identical to the score that serves, and a CI golden test asserts PostGIS ST_Contains over materialized cell polygons agrees with that function for a sampled grid. Tiles (Martin MVT live + Tippecanoe->PMTiles static on R2/CDN, MapLibre) are version-pinned to the same catalog_snapshot_hash as the API so the map can never disagree with the score or imply finer precision than the cell.

**Bileşenler:**

- **Geocoding Resolver** — Address string -> lat/lon + geocode_confidence + error_radius_m + match_type, KVKK-safe (Turkish addresses resolved in-region). Primary path is self-hosted; commercial fallback is confidence-scored and DPA-bound; sub-threshold matches are flagged needs_manual_review and routed to a human-in-the-loop queue rather than silently scored. Raw address is transient (request-scoped); only sha256(normalized address)->lat/lon is cached. _(Self-hosted Nominatim/Pelias on an OSM-Turkey extract (Fly.io EU/Frankfurt), commercial geocoder as flagged fallback, geocode_cache table in Postgres keyed by addr_hash with a KVKK retention TTL.)_
- **Spatial Resolver (point -> unit)** — Deterministically map lat/lon to a spatial unit and a resolution_level. Phase 1: hazard_zone cell via the shared point_to_cell() (the exact build_cell_index bin math). Roadmap: fine_grid then cadastral parcel via ST_Contains. Computes resolution_confidence from distance-to-cell-edge vs geocode error radius. Backed by PostGIS ST_Contains over materialized polygons AND the closed-form bin formula, asserted equal in CI. _(Shared eyequake.web.export.point_to_cell() imported verbatim; PostGIS 3.4 ST_Contains/ST_DWithin over GIST-indexed geometry; SQLAlchemy 2.0 + GeoAlchemy2.)_
- **PostGIS Spatial Store + Indexes** — Single source of geospatial truth: events (time-partitioned, BRIN+GIST), hazard_cells (0.25 deg polygons keyed by cell_id matching build_cell_index), site_layer, fine_grid/parcels/buildings (densification roadmap), and the versioned materialized risk_surface (published vs staging). Enforces tenant isolation (RLS) and feeds both the read API and the tile server. _(PostgreSQL 16 + PostGIS 3.4 managed in EU/Frankfurt; GIST spatial indexes; BRIN time index; Row-Level Security; Alembic migrations.)_
- **Risk Surface Materializer** — Offline (batch worker) job that runs build_cell_index + site.py + evaluate bootstrap CI + baseline skill, then UPSERTs the scored surface into risk_surface keyed by (unit_kind, unit_id, model_version, catalog_snapshot_hash). Does incremental rescore of only event-affected cells on new AFAD events and sets stale_post_mainshock. Publish is gated: a surface only flips staging->published if beats_baseline is true for every unit (the run_pipeline honesty gate). _(Separate batch-worker process (failure isolation), src/eyequake imported verbatim, pgmq trigger, content-hashed Parquet snapshot on R2 as the reproducibility anchor.)_
- **Score Read Service** — Thin, stateless synchronous read over the published risk_surface. Resolves point -> unit, fetches the precomputed row, assembles the honesty envelope, and passes it through the runtime Pydantic honesty validator before returning. Never computes a score; predictable p99. Handles the no-data-cell case with an explicit background floor (not fabrication, not null-silent). _(FastAPI + Pydantic v2 endpoint inside the modular monolith, read-replica friendly, per-tenant scoped API key + RLS.)_
- **Portfolio Batch Lookup** — Insurer uploads CSV of thousands-to-millions of parcels; layer validates schema, enqueues, bulk-geocodes, does one set-based PostGIS spatial join against the published surface, and writes a scored result file + a separate rejected-rows file (partial success is first-class, rows are never silently dropped). Idempotency keyed on (tenant, upload_hash, row_id). _(pgmq durable queue, batch-worker process, ST_Contains bulk join, results as CSV+GeoJSON on Cloudflare R2 with signed-URL delivery.)_
- **Vector Tile Service** — Serves the map: live layers (risk surface + AFAD events) as MVT straight from PostGIS, and the static hazard surface as PMTiles on CDN. Every tile feature carries resolution_level + model_version + catalog_snapshot_hash so the legend states '~25 km' and the map can never imply parcel precision or drift from the API version. _(Martin (Rust MVT) reading PostGIS, Tippecanoe->PMTiles on R2/Cloudflare CDN, MapLibre GL JS + deck.gl overlays, SRID 4326 storage / 3857 tiles.)_
- **Resolution-Honesty Envelope (cross-cutting)** — Guarantees every score (single, portfolio row, and tile property) carries resolution_level, nominal_meters, geocode_confidence, resolution_confidence, building_trust (none|self_reported|official), uncertainty (bootstrap CI), baseline_comparison, AFAD provenance, and the 'tahmini' disclaimer. Structurally blocks level=parcel while densification is disabled. _(Shared Pydantic v2 ScoreEnvelope model used by API, portfolio writer, and tile property builder; CI banned-claim linter extends test_web_honesty.py.)_

**Veri akışı:** SINGLE LOOKUP: client -> POST /v1/score {address | lat,lon} -> Geocoding Resolver (in-region; returns lat/lon + geocode_confidence + error_radius_m, or 422 needs_manual_review on no/low match) -> Spatial Resolver: point_to_cell(lat,lon) bin math + PostGIS ST_Contains over hazard_cells -> cell_id + resolution_confidence -> Score Read Service SELECTs the precomputed row from risk_surface WHERE publish_state='published' AND ST_Contains(geom,point) (or background-floor row if the cell has no historical M>=4 data) -> assemble ScoreEnvelope (score + uncertainty CI + baseline skill + AFAD provenance + staleness + resolution-honesty flags + disclaimer) -> Pydantic honesty validator REJECTS if any of model_version/provenance/uncertainty/baseline_comparison/'tahmini' missing or if level=='parcel' while densification off -> append to immutable score_audit (addr_hash, never raw address) -> 200. MAP: MapLibre loads PMTiles (static) or /v1/tiles/{z}/{x}/{y}.mvt (live) -> features carry resolution_level + model_version so legend shows '~25 km, NOT parcel'.

**Contract'lar:**

- `Authoritative point->cell formula (shared, reproducibility-critical)` — lat_bin = floor((lat - 35.5) / 0.25); lon_bin = floor((lon - 25.5) / 0.25); cell_center_lat = 35.5 + (lat_bin+0.5)*0.25; cell_center_lon = 25.5 + (lon_bin+0.5)*0.25; cell_id = f"{lat_bin:03d}_{lon_bin:03d}". IDENTICAL to src/eyequake/web/export.py:36-37 (build_cell_index). MUST be extracted into eyequake.web.export.point_to_cell(lat,lon,region,cell_deg) and imported by BOTH the materializer and the resolver. nominal_meters = 0.25*111320 ~= 27.8 km (lat), ~21.6 km (lon @ 39N) -> reported as ~25 km hazard_zone.
- `resolution_confidence formula` — boundary_margin_m = ST_Distance(point::geography, ST_Boundary(cell.geom)::geography); cell_assignment_conf = clip01(boundary_margin_m / max(geocode_error_radius_m, 1)); resolution_confidence = min(geocode_confidence, cell_assignment_conf). **Failure mode'lar:**

- _SUCCESS: address geocodes high-confidence and falls in a populated cell_ → Return full ScoreEnvelope, level=hazard_zone, resolution_confidence high; append to score_audit; metering event written transactionally.
- _EMPTY: geocoder returns no match_ → 422 needs_manual_review, no score fabricated; row routed to human-in-the-loop queue; portfolio equivalent goes to failed_url with reason, never scored as 0.
- _PARTIAL (single): geocode succeeds but confidence below threshold_ → Still resolve to cell (25 km tolerant) but stamp geocode_confidence + resolution_confidence low and flag low_confidence; surface the flag in UI; optionally route to HITL. Honest, not hidden.
- _EDGE: point in TURKEY bbox but cell has no historical M>=4 events (aseismic land / sea)_ → Do NOT return null silently and do NOT fabricate. Serve an explicit background_floor row (regional Poisson background baseline) with data_sufficiency:"background_floor" + wide CI; flagged so it cannot be mistaken for a data-backed score.
- _EDGE: point outside TURKEY bbox (25.5-45.0, 35.5-42.5)_ → 422 out_of_coverage with the covered region echoed; no score; tiles simply have no feature there.
- _PARTIAL (portfolio): some rows malformed / un-geocodable in a large CSV_ → Schema-invalid rows rejected at upload with row-level reasons; un-geocodable rows written to a separate failed_url file; status=partial with scored/failed counts. Rows never silently dropped or zero-filled.
- _ERROR: PostGIS read path unavailable_ → Synchronous /v1/score returns 503 with Retry-After; the MAP degrades gracefully to the last-good static PMTiles (flagged 'serving cached surface, version X') so exploration survives a DB blip; precompute-then-serve means the surface is also restorable from R2 Parquet snapshot.
- _DOMAIN: scores are stalest right after a mainshock (when demand peaks) because precompute lags_ → Incremental rescore of only event-affected cells triggered on each new AFAD event; until rescore completes, affected rows carry stale_post_mainshock=true surfaced in API + UI banner. Staleness is a monitored, visible signal, not a hidden SLA failure.
- _INTEGRITY: tiles and API drift to different catalog/model versions_ → Both pinned to catalog_snapshot_hash; a mismatch between served PMTiles and published risk_surface auto-flags on the integrity dashboard and blocks the tile publish step.
- _INTEGRITY: a payload would ship without uncertainty/baseline/provenance or labeled level=parcel before densification_ → Runtime Pydantic honesty validator REJECTS the response (500 internal, alerted) rather than serving a non-compliant or false-precision score; mirrored by the publish-time gate and CI banned-claim linter (defense in depth).
- _KVKK: a Turkish address would be geocoded by an out-of-region provider, or raw addresses would be persisted_ → In-region geocoder is primary; commercial fallback only under DPA with resolved_in_region recorded; geocode_cache stores sha256(address)->lat/lon, never raw address; cache TTL bounded by retention policy; score_audit stores addr_hash/latlon, never the raw address; every score/portfolio access is logged for DSAR/erasure.
- _ABUSE/SCALE: a multi-million-row portfolio or duplicate floods the worker_ → Per-tenant row cap + rate limit at the edge; CSV streamed not buffered; dedupe + Idempotency-Key prevents double billing/double work; queue-depth autoscaling + DLQ for poison jobs; batch worker isolated from the API event loop so it cannot starve synchronous p99.

### 6.5 — api-integration

Public insurer-facing REST API for EyeQuake: a thin, stateless FastAPI/Pydantic-v2 read layer over the precomputed PostGIS risk surface that exposes single-parcel scoring, async batch portfolio jobs, and building-card submission. Its defining constraint is the runtime honesty envelope: EVERY 2xx score payload is a required Pydantic model that fails closed unless it carries score/model_version, data provenance (source=AFAD + catalog_snapshot_hash + feed staleness), bootstrap-CI uncertainty, naive-baseline comparison (skill vs Poisson/mean/persistence), an explicit resolution-granularity flag, and a 'deprem tahmini DEĞİLDİR' (NOT earthquake prediction) disclaimer containing the literal token 'tahmini'. This makes the API the third enforcement point of the non-negotiable integrity layer (alongside the publish-time run_pipeline gate and the CI banned-claim linter). Versioning is dual: a stable URL major (/v1) for the API contract, plus an independent CalVer model_version in every payload so a priced score is byte-identically re-derivable for actuarial audit. Auth is per-tenant hashed scoped API keys with Postgres RLS; batch and building-card writes require Idempotency-Key for safe retries; rate limits + plan quotas + transactional Stripe metering are enforced at the edge. In Phase 1 the resolution flag honestly reports hazard_zone_0.25deg (~25 km cell average), NOT a parcel score — parcel granularity is gated on Phase-2 densification so the API cannot itself commit a false-precision integrity violation.

**Bileşenler:**

- **ASGI API app + OpenAPI publisher** — Single modular-monolith app exposing the /v1 insurer REST surface and the dashboard BFF; routing, request/response validation, auto-generated OpenAPI 3.1 + Swagger/ReDoc whose schema descriptions themselves carry the disclaimer. Body: {"year_built":1998,"floors":6,"structure_type":"rc_frame|masonry|steel|unknown","label":"Block A"?}. 201 → {"building_card_id":"bc_...","derived_fragility_class":"C2","trust":"self_reported","content_hash":"sha256:...","disclaimer":{"tr":"Kullanıcı beyanı; resmi yapı verisi DEĞİLDİR.","self_reported":true}}. Same content_hash → returns existing card (idempotent). trust is always surfaced so a self-reported card can never masquerade as official building data.
- `Auth & API-key data model` — Key format: Authorization: Bearer eyq_live_<key_id>_<secret> (eyq_test_ for sandbox). Lookup by key_id prefix → constant-time argon2id verify of secret. api_key(id, tenant_id, key_id_prefix UNIQUE, secret_hash, scopes TEXT[] in {score:read, portfolio:write, buildingcard:write, provenance:read}, status in {active,revoked}, created_at, last_used_at, rotated_from). - `Runtime honesty validator rule (the non-negotiable)` — ScoreResponse Pydantic v2 model: provenance, uncertainty, baseline_comparison, resolution, disclaimer are REQUIRED (not Optional). @model_validator(mode='after') asserts: disclaimer.tr contains 'tahmini' AND disclaimer.not_prediction is True AND disclaimer.not_early_warning is True; uncertainty.ci is a length-3 [lo,mean,hi] with lo<=mean<=hi; baseline_comparison.baselines ⊇ {poisson_background,mean,persistence} and skill_score present; provenance.source == 'AFAD' and catalog_snapshot_hash present; resolution.resolution_flag set (Phase 1 must be hazard_zone_average, NOT a parcel claim). This is the request-time analog of run_pipeline.validate_outputs (source==AFAD, disclaimer 'tahmini', required hazard props).

**Failure mode'lar:**

- _Success — in-region point, fresh surface, valid key/quota_ → 200 ScoreResponse with full honesty envelope; usage_event + score_audit written in same transaction; RateLimit/X-Quota headers returned.
- _Empty input — portfolio with 0 rows / score with no query_ → 422 VALIDATION_ERROR at submit (reject early, clearer than an empty job). Empty building card → 422 BUILDING_CARD_INVALID.
- _Out-of-region point (e.g. lat 50, outside config.TURKEY bbox)_ → Hard 422 OUT_OF_REGION — never extrapolate a score where the AFAD catalog has no coverage (integrity: no data → no score).
- _Low-confidence geocode (Turkish address ambiguous)_ → 422 GEOCODE_LOW_CONFIDENCE with geocode_confidence + remediation (supply lat/lon or finer address); if tenant opted into HITL, 202 routed to human-review queue. Never silently serve a wrong-cell score.
- _Sparse cell — few events / below magnitude-of-completeness_ → Still 200 but with a data_sparsity flag, a WIDER bootstrap CI, and the false-reassurance guard ('low observation does NOT mean safe', matching test_web_honesty.test_false_reassurance_guard). Low observation is never rendered as low risk.
- _Post-mainshock staleness — scores stalest exactly when most demanded_ → Serve last materialized score as 200 with staleness_flag=post_mainshock_stale + feed_lag_minutes (from live_meta); incremental rescore catches up. Honest degradation, surfaced in envelope, never a fabricated-fresh value.
- _AFAD feed outage / catalog snapshot aging_ → Serve stale-flagged scores (200); provenance shows the old data_vintage + feed_status=stale. USGS FDSN fallback feeds ingestion upstream. Freshness is never faked.
- _Model/surface not yet published for the region or pinned version_ → 503 MODEL_NOT_PUBLISHED / NO_SCORE_SURFACE + Retry-After; precompute decoupling means this is a clean unavailability, not a half-computed score.
- _Honesty envelope cannot be assembled (missing baseline or CI for a cell)_ → Fail closed: 500 HONESTY_ENVELOPE_VIOLATION + page. A score without provenance/uncertainty/baseline is treated as a defect, never shipped. This is the strongest invariant.
- _Partial portfolio — some rows out-of-region / low-confidence / unscorable_ → Job completes with status=partial; result file has one row per input row_id with status + per-row error code; progress counts scored/failed/low_confidence. No row is silently dropped.
- _Idempotency replay vs conflict on batch/building-card_ → Same key+body → replay stored response. Same key+different body → 409 IDEMPOTENCY_KEY_CONFLICT. Concurrent in-flight duplicate → 409/425. 24h key TTL.
- _Rate limit / quota exceeded_ → 429 RATE_LIMITED (Retry-After) or 429 QUOTA_EXCEEDED (X-Quota-* headers); read path unaffected for other tenants (per-key counters).
- _Auth failures — missing/revoked key, wrong scope, cross-tenant access_ → Missing/revoked → 401 UNAUTHENTICATED; wrong scope → 403 FORBIDDEN_SCOPE; accessing another tenant's job/card → 404 (RLS + app check, no existence leak).
- _Stripe metering push failure_ → usage_event persists with stripe_pushed_at NULL; reconciler retries with backoff; serving never blocked on billing. Billable units are eventually-consistent but transactionally durable (never lost).
- _Oversized portfolio submit_ → 413 PORTFOLIO_TOO_LARGE with documented max_rows; client chunks or uses R2 signed-URL multipart input path.
- _Cell-boundary / determinism edge (point exactly on a 0.25deg grid edge)_ → Deterministic ST_Contains with a defined tie-break (lower-left-inclusive) so the same point always maps to the same cell — required for byte-identical re-derivation.

**Tasarım kararları:**

- **Single-score is POST with the query in the body, not GET with query params:** POST /v1/score { query: {address|lat,lon} } — Addresses are personal data under KVKK/GDPR; keeping them out of URLs prevents leakage into access logs, CDN cache keys, and referer headers. Cost: not HTTP-cacheable by URL — acceptable because the read is already sub-100ms off the materialized surface.
- **Runtime honesty envelope as a fail-closed required Pydantic model:** ScoreResponse with non-optional provenance/uncertainty/baseline/disclaimer + model_validator; violation → 500, paged — Makes the API the third enforcement point of the non-negotiable integrity layer (publish gate + CI linter + runtime). It is physically impossible to emit a score lacking provenance, uncertainty, baseline comparison, or the 'tahmini' disclaimer — defense-in-depth that survives product/marketing pressure.
- **Dual versioning — stable URL major + independent CalVer model_version in payload:** /v1 for contract, model_version per response, pin-able for re-derivation — Decouples API contract evolution from scientific model evolution. A priced underwriting score must be byte-identically re-derivable years later for actuarial/regulatory audit, which a single API version cannot express; the content-hash materialization key (catalog_snapshot_hash, grid_params, site_inputs, building_card_version, model_version) guarantees reproducibility.
- **RFC 9457 problem+json with a stable machine-readable code enum:** application/problem+json + code field, cross-tenant → 404 — Insurer clients automate against errors; a stable code enum + structured domain fields (geocode_confidence, retry_after) is evolvable and unambiguous. Returning 404 (not 403) on cross-tenant access avoids leaking resource existence.
- **Precompute-then-serve thin read with src/eyequake imported verbatim:** ST_Contains on materialized parcel_risk_surface + joined model_eval; no compute in request path — Predictable p99 and failure isolation: a pipeline/feed failure degrades to serving stale-flagged scores (200) instead of an outage. Importing src/eyequake verbatim means the code that backtests in evaluate.py is the code whose materialized output is served — zero research/production drift, itself an integrity requirement.
- **Idempotency-Key mandatory on batch + building-card writes:** 24h-stored idempotency_key table; replay/conflict semantics — Network retries of an expensive portfolio submit must not double-charge or double-enqueue. Exactly-once submission is a correctness and a billing-integrity requirement.
- **Transactional metering via outbox, reconciled to Stripe:** usage_event written in the serving transaction; async push to Stripe — Billing must never lose a billable unit, and serving must never block on Stripe availability. Writing the meter in the same DB transaction as the audit row makes it durable; async reconciliation keeps the hot path fast.
- **Phase-1 resolution honesty flag = hazard_zone_0.25deg, parcel claim gated:** Every response carries resolution.granularity + resolution_flag=hazard_zone_average until Phase-2 densification — The verified 0.25deg (~25 km) grid is a hazard-zone average, not a parcel score; emitting it as 'parcel-level' would itself violate the honesty layer. The schema is shaped (separate resolution block, query-time BIS multiplier) to absorb densification without a breaking change.
- **pgmq for the batch queue, batch worker as a separate process:** Postgres-backed pgmq + dedicated Fly.io worker, not Celery/Redis yet — One fewer managed dependency pre-revenue for a 2-person team; the separate worker process means a heavy portfolio job cannot starve the API event loop. Graduate to Redis/ARQ only on measured need.
- **Per-tenant hashed scoped API keys + Postgres RLS in app AND DB:** argon2id key secrets, scopes, SET LOCAL app.tenant_id, RLS policies — Machine-to-machine insurer integrations need rotatable, least-privilege credentials; enforcing tenant isolation at BOTH the application and the database means a portfolio join can never cross tenants even if app code has a bug.

**Test:** Honesty contract test (HARD CI gate): property-based fuzz (Schemathesis) of /v1/score asserting EVERY 2xx validates ScoreResponse — provenance(source=AFAD, catalog_snapshot_hash), uncertainty(ci length 3), baseline_comparison(⊇ poisson/mean/persistence), resolution_flag, disclaimer containing 'tahmini' & not_prediction=True. A deliberately stripped envelope MUST return 500, never 200.; Banned-claim linter extended to the API surface: OpenAPI descriptions, field docs, disclaimer copy and error messages must never contain 'earthquake prediction' / 'forecast of date-place-magnitude' / 'neural-net prediction' / 'early warning' as a positive claim; 'tahmini' must appear in disclaimers (extends tests/test_web_honesty.py).; Idempotency tests: same key+body → identical response; same key+different body → 409; concurrent duplicate submit race resolves to one job.; Rate-limit & quota tests: burst → 429 + RateLimit headers; period rollover resets quota; per-tenant isolation of counters.; RLS tenant-isolation test (DB + app level): tenant A key cannot read tenant B portfolio_job / building_card / score_audit (asserts 404, not 403).; Geo edge tests: out-of-region 422; low-confidence geocode 422/HITL; exact 0.25deg cell-boundary determinism (ST_Contains tie-break).; Portfolio lifecycle tests: empty(422)/single/N/partial-failure(status=partial, one output row per input)/oversized(413); poll queued→running→succeeded; signed result URL expiry.; Reproducibility test: same (catalog_snapshot_hash, model_version, query) → byte-identical score_id + response_hash (actuarial audit requirement).; Auth tests: key creation shows secret once; rotation dual-valid window; revocation → 401; scope enforcement → 403.; Staleness test: simulate post-mainshock / feed lag → staleness_flag + feed_lag_minutes surface in envelope, still 200 (degrade not fail).; Provenance consistency test: GET /v1/provenance/{model_version} hashes match the catalog_snapshot_hash embedded in served scores.; Load/stress test (k6): /score p99 under concurrency against the materialized surface; batch path against a realistic ~1M-row portfolio before any contractual SLA.

**Açık sorular:**

- Synchronous /score SLA target (p99 ms) and per-plan burst rate limits / quota units — need design-partner pilot numbers to set defaults.
- Geocode-confidence threshold for hard-reject (422) vs human-in-the-loop routing — must be tuned against real Turkish address data; what is the acceptable mis-resolution rate before a score is underwriting-safe?

### 6.6 — dashboard-frontend

Insurer-facing dashboard for EyeQuake: a Next.js 15 (App Router) + React 19 + TS-strict + Tailwind 4 + shadcn/ui app deployed on Vercel (EU), separate from the FastAPI API. It is a thin presentation tier over the FastAPI "dashboard-BFF" read path, with its own Node-runtime BFF proxy (Next route handlers) that holds the WorkOS session, attaches tenant context + a server-side service credential, and RE-VALIDATES every score payload against a Zod mirror of the Pydantic honesty schema (defense-in-depth: a bare risk number is unrepresentable in the type system and unrenderable in the UI). Optional building card: {building_age|year_built, floors, structure_type:'rc_frame|masonry|steel|other'} -> fragility_class (self_reported trust). Client rejects pre-submit if 0 rows, missing required columns, or >cap rows for plan. Mapping UI lets user bind arbitrary headers to canonical fields. Drives <StalenessFlag>; status='stale' OR post-mainshock rescore-in-progress -> persistent banner with data_vintage; banner is NEVER hidden (mobile included).

**Failure mode'lar:**

- _Honesty envelope incomplete (payload missing uncertainty/baseline/provenance/resolution/disclaimer, or disclaimer lacks 'tahmini')_ → BFF Zod .parse() fails -> 502 {error:'honesty_violation', missing}. UI renders an integrity-error card ('Skor bütünlük kontrolünü geçemedi — gösterilemiyor'), NEVER a bare number. High-severity Sentry event + pages on-call. This is the non-negotiable guard, enforced at FastAPI AND the BFF edge AND the component type system.
- _Model stops beating naive baseline (baseline_comparison.verdict = beats_none / beats_some)_ → Score still returned but UI shows a prominent red warning ('Model şu an naif baseline'ı geçmiyor — pricing için kullanılamaz'); export and any pricing-use CTA are DISABLED; the <BaselineComparison> panel is expanded by default. Consistent with the integrity publish-gate.
- _Geocode low-confidence_ → geocode_status='low_confidence' -> do NOT silently score as confident; show ranked candidate picker (human-in-the-loop) + map-pin confirm; the chosen result re-scored with geocode_confidence surfaced on the <ResolutionConfidenceBadge>.
- _Geocode failed / address not found_ → Empty state: 'Adres bulunamadı. Lat/lon girin veya haritadan nokta seçin.' No score rendered; offer manual coordinate entry.
- _Post-mainshock staleness / data lag_ → live_meta status='stale' or rescore-in-progress -> persistent (never-hidden, mobile-included) banner showing lag_minutes + data_vintage; scores still served from precompute surface but flagged stale; matches the precompute-then-serve degrade-not-outage design.
- _Portfolio partial result (some rows scored, some unresolved)_ → status='partial' -> render scored rows + a distinct 'Çözümlenemeyen satırlar' tab (geocode failures/low-confidence) with a download for fix-and-resubmit; summary states n_scored / n_unresolved explicitly; partial is a first-class state, not an error.
- _Empty or malformed portfolio CSV (0 rows, missing required columns)_ → Client-side validation before submit; inline column-mapping UI with field-binding errors; empty result set after scoring -> empty state with guidance, no spinner-forever.
- _Very large portfolio (up to ~1M rows)_ → Streamed signed upload to R2 (browser never holds whole file beyond preview), async pgmq job + progress polling, virtualized table (TanStack Virtual), deck.gl aggregation/clustering instead of 1M DOM markers; map degrades to heatmap above a point threshold.
- _API 5xx / timeout / network drop_ → Bounded TanStack Query retry with exponential backoff, route-level error boundary with 'tekrar dene' CTA, offline-detection banner; never an infinite spinner.
- _Auth expired / 401 from BFF_ → Middleware redirects to WorkOS login preserving return URL; in-app 401 attempts silent session refresh, else redirect; in-flight unsaved portfolio mapping is persisted to local draft.
- _RBAC denied (403, e.g. read-only tries export, analyst tries team admin)_ → UI hides/disables actions per role AND BFF returns 403 (defense-in-depth; DB RLS is source of truth). Friendly 'Bu işlem için yetkiniz yok' message; UI gating is UX only, never the security boundary.
- _Quota exceeded / rate limited (429)_ → Quota -> banner 'Kota doldu — plan yükseltin' + Stripe portal link, new scoring blocked, usage page surfaced. Rate-limit -> toast + backoff; request auto-retried after Retry-After.
- _Map tile load failure_ → Graceful degradation: fall back to lower-detail PMTiles, then to a 'harita yüklenemedi' placeholder while the table/report remain fully usable (map is an enhancement, not a dependency).
- _Resolution false-precision risk (Phase 1 hazard-zone mislabeled as parcel)_ → <ResolutionConfidenceBadge> reads granularity strictly from the envelope; in Phase 1 it always renders 'hazard-zone ~25 km, parsel çözünürlüğü değildir'. A snapshot test asserts the word 'parsel' is never shown as the resolution while granularity='hazard_zone'.
- _Single score with site layer but no building data (BIS trust=none)_ → Success state (not error): render hazard×site score with a 'Bina verisi yok — sadece hazard×site' note and BuildingTrustFlag=none; invites user to add a building card to refine.
- _Export generation failure / long PDF_ → Toast + retry; large reports run async with a 'hazır olduğunda indirilebilir' notification + download from jobs list; partial export never produced without provenance.

**Tasarım kararları:**

- **Put a Node-runtime Next BFF proxy in front of FastAPI rather than calling the API directly from the browser:** All score traffic goes client -> /api/bff/* -> FastAPI — Keeps the per-tenant service credential server-side, lets us mirror the Pydantic honesty validator in Zod as a second enforcement point, gives single-origin (no CORS/secret exposure), and routes insurer addresses (PII) through our logged EU server for KVKK — directly realizing the locked 'runtime honesty validator at the boundary' and residency requirements.
- **Make the honesty envelope a non-optional component+type contract:** A <RiskScoreCard> is constructible only from a Zod-validated ScoreEnvelope; a bare risk number has no renderable type — Turns the non-negotiable scientific-integrity rule into a compile-time + runtime invariant instead of a convention a future dev could forget — uncertainty, baseline verdict, provenance, resolution and the 'tahmini' disclaimer cannot be omitted.
- **Self-hosted MapLibre + Martin/PMTiles, deck.gl only for big overlays:** No Mapbox token; base map light, deck.gl reserved for portfolio aggregation — KVKK in-region tiles, no per-call SaaS map cost, no vendor lock-in (locked-stack mandate); deck.gl clustering keeps 1M-row portfolios renderable without 1M DOM markers.
- **Async portfolio via job polling + signed R2 result URL, not inline streaming:** POST returns job_id; client polls; results downloaded from R2 — Matches the backend pgmq async contract, handles million-row portfolios and partial results, and keeps browser memory + request-path p99 predictable.
- **Server-generated (FastAPI) PDF/CSV exports, not client-rendered:** Exports built server-side and byte-identical to the audit record — An underwriting artifact must be reproducible and provenance-stamped (model_version, data_vintage, snapshot_hash, disclaimer); client-rendered PDFs could drift from the audited score and weaken actuarial/regulatory defensibility.
- **RBAC enforced in UI and BFF, but DB RLS remains the security boundary:** UI gating = UX; BFF 403 = defense-in-depth; RLS = truth — Prevents a portfolio join ever crossing tenants while keeping a clean role-aware UX; UI must never be trusted as the access control.
- **Resolution + building-trust badges mandatory on every score, Phase 1 fixed to 'hazard-zone':** Every score view shows granularity ~25 km + geocode confidence + building trust — Neutralizes the #1 honesty risk (false parcel precision) at the presentation layer independently of the backend, until Phase-2 cadastral densification makes 'parcel-level' honest.
- **Separate Vercel deploy for the frontend, with the public honesty site SSR/SSG:** Frontend independent of the API tier; methodology/not-prediction pages edge-cached + indexable — Independent scaling/rollback, and the 'this is NOT earthquake prediction' framing + model card stay first-class and available even if the app/API is down — legally and reputationally important.
- **TanStack Query as the single server-state layer with MSW-based tests:** All fetching/polling/caching through TanStack Query; MSW mocks the BFF — Uniform, contract-testable handling of loading/error/empty/partial/success across every view; polling for portfolio jobs and live staleness is first-class.

### 6.7 — auth-billing-tenancy

Production design for EyeQuake's auth + multi-tenancy + billing layer, implemented as modules inside the FastAPI modular monolith (Python 3.11, Pydantic v2, SQLAlchemy 2.0 + GeoAlchemy2, Alembic, Postgres 16 + PostGIS on Fly.io EU/Frankfurt). Two auth planes: WorkOS SSO/SAML + SCIM for the Next.js dashboard (cookie session), and server-side hashed scoped per-tenant API keys (argon2id) for the machine-to-machine insurer API. Tenant isolation is defense-in-depth: app-level org filter AND Postgres Row-Level Security keyed on org_id, gated by an integration test that proves cross-tenant reads return zero. Billing is Stripe Billing usage-metered (per parcel scored / per call / per portfolio row) + seat tiers, but with a critical inversion: a local meter_events table is the source of truth, written TRANSACTIONALLY with each scored request and reported to Stripe asynchronously, so billing correctness and scoring p99 are both independent of Stripe uptime. The non-negotiable integrity x billing rule: a score is metered/billable ONLY if it returned 2xx AND passed the runtime honesty-schema validator (provenance + bootstrap CI + baseline_comparison + 'tahmini' disclaimer) — EyeQuake never bills for a payload it would refuse to ship. Turkish customers get KDV (20%) + legal e-Arsiv/e-Fatura via a GIB integrator (Parasut) overlaid on Stripe, with VKN/TCKN validation; international reinsurers get EUR/USD + Stripe Tax + VIES reverse-charge VAT. An immutable per-score audit log backs underwriting/KVKK defensibility.

**Bileşenler:**

- **Identity & Session (dashboard auth plane)** — Enterprise SSO login for the insurer dashboard: SAML/OIDC via WorkOS, SCIM directory sync (auto provision/deprovision of underwriters), signed server-side session cookie carrying user_id/org_id/role. Maps WorkOS organizations to internal orgs; routes the OAuth callback; refreshes/revokes sessions. _(WorkOS (primary, SSO/SAML/SCIM) with Clerk as faster-to-ship pilot fallback; FastAPI dependency that resolves the session into a TenantContext; httpOnly/SameSite=strict signed cookie; Next.js 15 BFF route for the callback.)_
- **API Key Service (machine auth plane)** — Lifecycle of per-tenant M2M API keys for the insurer scoring API: create (returns plaintext once), list (metadata only), rotate (with grace overlap), revoke, scope checks, last_used tracking. Verifies inbound Bearer keys by prefix lookup + argon2id hash compare; loads org + scopes into TenantContext; optional mTLS for high-assurance pilots. _(argon2id hashing (passlib), key format eq_live_/eq_test_ + 8-char public prefix for fast indexed lookup; SQLAlchemy api_keys table; FastAPI security dependency; optional Cloudflare/Fly mTLS at the edge.)_
- **Tenant Isolation / RLS Enforcer** — Guarantees a portfolio batch join can never cross tenants. Every request opens a DB transaction and issues SET LOCAL app.current_org_id; all tenant-scoped tables carry org_id with a Postgres RLS policy USING (org_id = current_setting('app.current_org_id')). App-level repository filters add a second layer; a CI integration test asserts isolation. _(PostgreSQL 16 Row-Level Security; SQLAlchemy 2.0 session-bound SET LOCAL; shared-schema + tenant_id default, schema-per-tenant reserved for large reinsurers; GeoAlchemy2 for the PostGIS reads behind the scored endpoints.)_
- **RBAC / Authorization** — Role enforcement (admin / underwriter / analyst / read-only) on dashboard endpoints and key/billing management; scope enforcement (score:read, portfolio:write, billing:read) on API keys. Centralized policy so a read-only seat cannot mutate keys or trigger billable portfolio jobs. _(FastAPI dependency-injected permission guards; enum role column; scope[] on api_keys; policy table for plan-gated features.)_
- **Metering Engine** — Writes a meter_event row TRANSACTIONALLY in the same DB tx as the score_audit insert, ONLY when the response is 2xx and honesty_passed=true. Carries idempotency_key for exactly-once counting under retries (portfolio resume, network replays). Increments a fast usage_counter for quota checks. Records stale_flag and geocode_confidence for transparency. _(Postgres meter_events table with UNIQUE(idempotency_key); same SQLAlchemy unit-of-work as scoring; pgmq for the async Stripe reporter; Redis usage counters when rate-limit/hot-cache justifies graduation.)_
- **Quota & Rate Limiter** — Pre-scoring gate: per-tenant request rate limit (token bucket from plan.rate_limit_rps) and quota check (period usage vs plan included_quota). Hard-cap plans return 402 over quota; overage-enabled plans allow and accrue. Stops a partially-run hard-cap portfolio at the quota boundary and returns a partial result marker. _(Postgres advisory/counter limiter at MVP, graduating to Redis token bucket; plan config table; enforced at the API edge before src/eyequake is invoked.)_
- **Billing Orchestrator (Stripe)** — Owns subscriptions, plans, seats, checkout/upgrade, customer portal, and the async meter reporter that pushes local billable meter_events to Stripe Billing Meters. Computes overage. Reconciles local source-of-truth against Stripe-reported usage nightly and alerts on drift. _(Stripe Billing (usage-based meters + seat subscriptions) + Stripe Tax; pgmq-driven reporter with idempotency; Stripe customer portal; reconciliation cron on the scheduler process.)_
- **Tax & Invoicing (TR + international)** — Issues legally compliant invoices. Turkish orgs: KDV 20% + e-Arsiv/e-Fatura through a GIB integrator, VKN/TCKN validation, TRY. International reinsurers: Stripe Tax, EUR/USD, EU B2B reverse-charge via VIES-validated VAT number (0% with reverse-charge note). Mirrors invoice status (GIB UUID, KDV amount, PDF) locally. _(Parasut API (GIB e-fatura/e-arsiv) overlaid on Stripe invoices; Stripe Tax for international VAT; VIES VAT validation; local invoices table mirroring Stripe + GIB status.)_
- **Immutable Score Audit Log** — Append-only record of every scored request (org, user/api_key, resolved cell/parcel ref, model_version, data_vintage, catalog_snapshot_hash, provenance, uncertainty, baseline_comparison, disclaimer, stale_flag, geocode_confidence, timestamp) for underwriting/regulatory defensibility and KVKK access logging. One audit row per billable meter event (invariant). _(Postgres append-only table; INSERT-only role privileges + BEFORE UPDATE/DELETE trigger that raises; partitioned by month; feeds the Scientific-Integrity dashboard.)_
- **Webhook & Compliance Handlers** — Idempotently consume Stripe events (invoice.finalized, subscription updates, payment failures -> dunning/downgrade), WorkOS SCIM events (user provision/deprovision), and GIB-integrator status callbacks. Serve KVKK/GDPR DSAR endpoints (access/erasure) honoring the legal-obligation retention basis for the audit log. _(FastAPI webhook routes with signature verification; processed_webhooks dedup table keyed by provider event id; DSAR jobs via pgmq; data-residency tag on org selects region.)_

**Veri akışı:** DASHBOARD AUTH: browser -> WorkOS SSO (SAML/OIDC) -> /v1/auth/callback exchanges code, upserts user (SCIM-synced), issues signed session cookie (user_id, org_id, role). Every dashboard request: session dependency -> open DB tx -> SET LOCAL app.current_org_id = org_id -> RLS scopes all reads -> RBAC guard checks role.  MACHINE AUTH: insurer system -> Authorization: Bearer eq_live_<prefix><secret> -> API-key middleware parses prefix, indexed lookup, argon2id verify, reject if revoked/expired, load org+scopes -> open tx -> SET LOCAL app.current_org_id.  SCORING + METERING (single transaction): request -> rate-limit (token bucket per org) -> quota check (usage_counter vs plan.included_quota; hard-cap over quota => 402, overage plan => allow+accrue) -> call src/eyequake scoring over the materialized parcel_risk_surface (read-only) -> assemble response envelope (score + bootstrap CI + baseline_comparison + provenance{model_version,data_vintage,source=AFAD} + 'tahmini' disclaimer + geocode_confidence + stale_flag) -> runtime Pydantic honesty validator. PASS: within the same tx, INSERT score_audit (immutable) + INSERT meter_event(metric=parcel_scored, billable=true, honesty_passed=true, idempotency_key) + increment usage_counter -> COMMIT -> 200. FAIL: 422, rollback, ZERO meter rows (never bill a non-compliant payload).  ASYNC BILLING (decoupled): pgmq reporter reads unreported billable meter_events -> Stripe Billing Meter API (idempotent) -> mark reported_to_stripe_at. Stripe outage never blocks scoring or corrupts counts because the local row is the source of truth.  PERIOD CLOSE: Stripe builds invoice from meters + base + seats + Stripe Tax. TR org -> Parasut issues e-Arsiv/e-Fatura with KDV 20%; international EU B2B reinsurer -> reverse-charge note via validated VAT. Webhooks (stripe invoice.finalized, parasut GIB status) update local invoices table.  RECONCILE (nightly on scheduler): sum(local billable meter_events) vs Stripe-reported per org; drift -> page the integrity/ops dashboard. INVARIANT continuously checked: count(billable meter_events) per request == count(honesty_passed audit rows).

**Contract'lar:**

- `POST /v1/api-keys` — Auth: dashboard session, role in {admin}. Body {name: str, scopes: ["score:read","portfolio:write","billing:read"], expires_at?: iso8601}. 201 -> {id, name, key: "eq_live_AB12cd34_<secret>" (returned ONCE), prefix: "AB12cd34", scopes, created_at}. Subsequent GET /v1/api-keys returns metadata only (no secret). POST /v1/api-keys/{id}/rotate -> new secret + 24h grace where old key still verifies. DELETE /v1/api-keys/{id} -> sets revoked_at; immediate 401 on next use.
- `GET /v1/usage` — Auth: session(billing:read) or key(billing:read). Query ?period=2026-06. 200 -> {period, plan_code, included_quota: 50000, used: 41230, overage_units: 0, metric_breakdown:{parcel_scored:41230, portfolio_rows:38900, api_calls:41230}, projected_charge:{currency:"TRY", base_cents, overage_cents, kdv_cents, total_cents}, as_of: iso8601}. Empty period -> all zeros, 200 (never 404).
- `POST /v1/orgs/current/members + RBAC` — Roles enum: admin|underwriter|analyst|read_only. POST {email, role} -> WorkOS invite (or SCIM-managed => 409 directory_managed). PATCH /v1/orgs/current/members/{id} {role}. Permission matrix: read_only=score:read only; analyst=+portfolio:read; underwriter=+portfolio:write(billable); admin=+keys+billing+members. A read_only seat calling POST /v1/score/portfolio -> 403.
- `POST /webhooks/stripe` — Verify Stripe-Signature (raw body). Dedup on event.id via processed_webhooks (UNIQUE). Handle invoice.finalized (mirror to invoices, trigger Parasut e-fatura if org.country=TR), customer.subscription.updated (plan/seat/status sync), invoice.payment_failed (dunning: mark org past_due -> API returns 402 after grace, dashboard read-only). Always 200 after durable enqueue; 400 only on bad signature.
- `DB model: orgs / users / api_keys` — orgs(id uuid pk, name, slug uniq, country char(2), tax_id_type enum[vkn,tckn,eu_vat,other], tax_id text, vat_validated bool, data_residency_region text default 'eu-fra', stripe_customer_id, plan_id fk, status enum[trialing,active,past_due,canceled], created_at). users(id, org_id fk, email, workos_user_id, role enum, status, created_at). api_keys(id, org_id fk, name, key_prefix uniq, key_hash, scopes text[], created_by, last_used_at, expires_at, revoked_at, status). All tenant tables: RLS policy USING (org_id = current_setting('app.current_org_id')::uuid).
- `DB model: meter_events (source of truth)` — meter_events(id uuid pk, org_id fk, idempotency_key text UNIQUE, request_id, score_id fk->score_audit, metric enum[parcel_scored,api_call,portfolio_row], quantity int, model_version, data_vintage, catalog_snapshot_hash, honesty_passed bool NOT NULL, stale_flag bool, geocode_confidence numeric, billable bool NOT NULL, occurred_at timestamptz, reported_to_stripe_at timestamptz NULL, stripe_meter_event_id text NULL). CHECK (billable = false OR honesty_passed = true) -- DB-level guarantee a non-compliant score is never billable.
- `Billing formulas` — billable_units(period) = SUM(quantity) WHERE metric=parcel_scored AND billable=true AND occurred_at IN period (assigned by occurred_at, not report time). overage_units = max(0, billable_units - plan.included_quota). overage_charge = overage_units * plan.overage_unit_price_cents. is_billable(req) = http_2xx AND honesty_passed AND NOT duplicate(idempotency_key). TR total = (base + seats + overage) ; kdv = round(subtotal * 0.20) ; grand_total = subtotal + kdv. EU B2B reverse-charge (VIES-valid VAT): vat=0, note='reverse charge'.
- `POST /v1/billing/portal-session & invoices` — POST -> {url} Stripe customer portal (manage payment method, view invoices). GET /v1/invoices -> [{id, period, currency, subtotal_cents, tax_cents, total_cents, status, stripe_invoice_url, gib_status: enum[na,pending,issued,failed], gib_uuid?, einvoice_pdf_url?}]. TR invoices carry gib_uuid once Parasut confirms GIB acceptance.

**Failure mode'lar:**

- _Empty: brand-new org, no API keys, no usage, no subscription._ → GET endpoints return zeros/empty arrays with 200 (never 404). Org defaults to a trialing plan with a small included_quota; scoring works under trial; dashboard shows an upgrade CTA. No meter rows until first successful score.
- _Error: score response fails the runtime honesty validator (missing provenance / CI / baseline / 'tahmini')._ → Return 422 honesty_violation, roll back the transaction so NO score_audit and NO meter_event are written. Page the integrity dashboard. The CHECK(billable=false OR honesty_passed=true) constraint is a second guarantee the customer is never billed for a non-compliant payload.
- _Error: Stripe API down during usage reporting._ → Scoring is unaffected because meter_events is the local source of truth. The pgmq reporter retries with backoff + DLQ; reported_to_stripe_at stays NULL until success. Nightly reconciliation surfaces any lag. Billing correctness is never coupled to Stripe uptime or to the request path.
- _Partial: portfolio job (50k rows) crashes after 30k rows, then retries._ → Each row carries an idempotency_key (org_id+job_id+row_hash) with a UNIQUE constraint on meter_events; resume re-scores from a checkpoint and duplicate inserts are no-ops, so exactly-once metering holds. Only rows that returned 2xx AND passed honesty are metered; failed/low-confidence rows are returned flagged, not billed as success.
- _Domain edge: hard-cap plan hits quota mid-portfolio._ → Limiter stops billable scoring at the included_quota boundary, returns 207-style partial result with {scored_n, remaining_n, reason:'quota_exceeded'} and a 402 marker; overage-enabled plans continue and accrue overage_units. Quota check reads occurred_at-based usage_counter so period boundaries are deterministic (UTC).
- _Domain edge: cross-tenant data access attempt (crafted org_id, shared cell geometry)._ → Defense-in-depth: app repository filter on org_id AND Postgres RLS via SET LOCAL app.current_org_id. Even a raw spatial join (ST_Contains over shared PostGIS hazard cells) returns only the caller's rows because RLS filters portfolio/audit tables. A CI integration test asserts tenant B reading tenant A returns zero, and is a hard deploy gate.
- _Domain edge: post-mainshock stale score is served and metered._ → Stale scores remain billable (a delivered, honest, flagged result) but stale_flag=true is recorded on both score_audit and meter_event and surfaced in the API/UI; if it breaches an SLA freshness term the reconciliation/SLA job can auto-issue a Stripe credit note. Transparency over silent suppression.
- _Error: duplicate webhook delivery (Stripe/WorkOS/GIB)._ → processed_webhooks table with UNIQUE(provider,event_id); replays are acknowledged 200 but produce no second side effect. Subscription/dunning state transitions are idempotent (set-to-target, not increment).
- _Domain edge: Turkish e-fatura provider (GIB) rejects/queues an invoice._ → invoices.gib_status=pending; Parasut callback updates to issued/failed. On failed, alert finance + retry within the GIB legal window; Stripe payment is independent so cash collection is not blocked by e-fatura issuance lag. VKN/TCKN format validated at org-setup to prevent most rejections up front.
- _Error: payment failure / subscription canceled while API keys still active._ → Keys still authenticate (valid credentials) but authorization returns 402 payment_required after a configurable dunning grace; dashboard drops to read-only. Never silently keep serving billable scores to a delinquent tenant, and never hard-revoke keys (lets them recover by paying).
- _Success: normal scored API call._ → rate-limit pass -> quota pass -> honest score -> single tx writes one score_audit + one billable meter_event + counter increment -> 200 with full honesty envelope -> async reported to Stripe -> appears in GET /v1/usage and end-of-period invoice with correct KDV/VAT.

**Tasarım kararları:**

- **Meter only honesty-passed 2xx scores; enforce at the DB with CHECK(billable=false OR honesty_passed=true).:** Bind billing to scientific integrity at the data layer, not just app logic. — EyeQuake's non-negotiable honesty layer means a payload missing provenance/CI/baseline/'tahmini' must be refused (422). Billing for a refused payload would be both an integrity and a commercial-trust violation. A DB constraint makes 'never bill a non-compliant score' true even if app code regresses — defense-in-depth alongside the runtime validator and the run_pipeline publish gate.
- **Local meter_events is the billing source of truth; Stripe is reported to asynchronously.:** Decouple billing accuracy and scoring p99 from Stripe uptime. — A 2-founder team cannot let a Stripe blip block scoring or corrupt usage counts. Writing the meter in the same transaction as the score guarantees no lost/over-counted usage; the async reporter + nightly reconciliation give exactly-once Stripe sync with drift alerting. Matches the locked stack's 'metering written transactionally with each scored request, reconciled against observability'.
- **Defense-in-depth tenant isolation: app filter + Postgres RLS + CI isolation gate.:** RLS via SET LOCAL app.current_org_id on every tx, plus repository-level org filter, plus a hard test. — Portfolio batch joins over shared PostGIS hazard geometry are exactly where a forgotten WHERE org_id leaks a competitor insurer's book. Bus-factor demands the database refuse cross-tenant reads even when app code is wrong. Shared-schema+RLS keeps ops light; schema-per-tenant stays reserved for large reinsurers needing residency/scale isolation.
- **WorkOS primary for dashboard auth, Clerk as pilot fallback; argon2id scoped API keys for M2M.:** Enterprise SSO/SAML+SCIM for humans, hashed scoped keys for machines. — Insurers/reinsurers contractually require SAML SSO + SCIM deprovisioning; WorkOS delivers it without building IdP plumbing. Clerk ships faster for a first pilot that doesn't yet mandate SSO. Machine API needs revocable, rotatable, least-scope credentials with a prefix for indexed lookup and argon2id at rest — no shared bearer secret.
- **Stripe as billing engine + Parasut (GIB) e-fatura overlay for Turkey; Stripe Tax + VIES for international.:** Two-track tax/invoicing rather than forcing one provider. — Stripe cannot issue legally compliant Turkish e-Arsiv/e-Fatura (GIB mandate, KDV, VKN/TCKN). Parasut handles GIB; Stripe handles global subscriptions/metering/tax and EU B2B reverse-charge via VIES-validated VAT. Keeping payment (Stripe) independent of e-fatura issuance means GIB lag never blocks cash collection.
- **Idempotency keys on every meter/portfolio row + UNIQUE constraint.:** Exactly-once metering under retries and concurrency. — Portfolio jobs run on pgmq with at-least-once delivery and resumable checkpoints; without idempotency a retry double-bills an insurer — a trust-destroying error in underwriting. UNIQUE(idempotency_key) makes duplicate inserts no-ops even under race.
- **Data-residency tag on org (eu-fra default, Turkey-region option on roadmap) drives region.:** Tenant-level residency rather than a single global region. — Insurer portfolios contain addresses (personal data under KVKK; GDPR for EU reinsurers). EU/Frankfurt default satisfies GDPR and most contracts now; a Turkey-region option is reserved for Turkish insurers demanding in-country residency, with the self-hosted geocoder keeping addresses in-region.
- **Immutable append-only score_audit with one row per billable meter event.:** Append-only table (INSERT-only role + UPDATE/DELETE trigger) feeding the integrity dashboard. — Underwriting/regulatory defensibility and KVKK access logging require a tamper-evident record of who scored what, with which model_version/provenance, when. Tying it 1:1 to billable meters gives an auditable usage-to-money chain and powers the count(meter)==count(audit) invariant.

**Test:** Unit: billing formulas (included/overage/KDV 20%/EU reverse-charge), occurred_at-based period assignment, currency rounding (TRY/EUR/USD integer cents), VKN(10-digit)/TCKN(11-digit checksum)/EU-VAT format validation.; Unit: API key hash+verify (argon2id), prefix lookup, rotation grace overlap, revoked/expired rejection, scope enforcement per role.; Integration (HARD CI gate): RLS cross-tenant isolation — tenant B with a crafted org_id and a raw ST_Contains spatial join over shared hazard cells reads ZERO of tenant A's portfolio/audit rows.; Integration: metering-is-transactional — a 2xx honest score writes exactly one score_audit + one billable meter_event; an honesty-validator failure writes ZERO of both (asserts the CHECK(billable=false OR honesty_passed=true) constraint).; Integration invariant: per request_id, count(billable meter_events) == count(honesty_passed score_audit) — the billing x scientific-integrity link cannot drift.; Integration: webhook idempotency — replay the same Stripe/WorkOS/GIB event id; assert no double subscription change, no double invoice, no double meter.; Integration: quota enforcement — hard-cap plan returns 402 at boundary with partial portfolio result; overage plan accrues correctly; ### 6.8 — infra-deploy-cicd

Production infra/deploy/CI-CD layer for EyeQuake on Fly.io EU/Frankfurt: one stamped, signed container image with three Fly process groups (api / batch-worker / scheduler) sharing managed Postgres 16 + PostGIS 3.4 (Crunchy Bridge, PITR), Cloudflare R2 for content-hashed AFAD Parquet snapshots + PMTiles + exports, and Cloudflare in front for CDN/WAF/TLS. Three environments (dev = docker-compose, staging, prod) deploy through GitHub Actions that EXTEND the existing ruff+pytest gate with the run_pipeline.validate_outputs honesty contract, a banned-claim linter (graduated from test_web_honesty.py), Alembic expand/contract migration round-trip, and image scan/sign. Releases are blue-green with instant rollback. The decisive integrity move: the customer-facing risk surface is PUBLISHED via an atomic pointer-swap table that is DECOUPLED from code deploys, so (a) a code rollback never silently changes prices, (b) a model that stops beating its naive baselines is blocked at publish time and pages instead of shipping, and (c) the science can be rolled back independently of the binary. Precompute of the national grid runs in the isolated batch worker on a leader-locked scheduler (graduating watch_afad.py) with a GitHub Actions cron watchdog; the batch worker autoscales 0..N on pgmq queue depth for cost control while the API stays HA at min 2 machines. Honesty is enforced three times (CI linter, publish-time validate_outputs/skill_score gate, deploy-time runtime honesty probe) as defense-in-depth.

**Failure mode'lar:**

- _SUCCESS path — clean release_ → CI all-green -> image stamped+signed -> expand migration -> green boots -> smoke+honesty probe pass -> traffic shift -> deploy_audit(honesty_gate_pass=true). Blue retained one cycle for instant rollback.
- _CI honesty/baseline or banned-claim gate fails_ → run_pipeline --check or lint_claims.py exits nonzero -> branch protection blocks merge; no image is ever built. Surfaces the exact missing key (e.g. 'meta disclaimer must state forecast limits') in the PR check.
- _Migration fails mid-deploy_ → Alembic runs as Fly release_command BEFORE any traffic shift; nonzero exit aborts the deploy with blue still serving. Expand/contract discipline means the expand step is backward-compatible, so a half-applied expand never breaks live blue. CI already proved upgrade+downgrade round-trips on a PostGIS service container.
- _Green machines boot but readiness/honesty probe fails_ → No traffic shift. flyctl deploy --strategy rollback removes green; blue keeps serving the prior image. Pager fires. deploy_audit.rolled_back=true. Common cause: missing secret (readyz fails closed) or honesty envelope regression caught by /internal/honesty-selfcheck.
- _ERROR — AFAD feed outage during precompute_ → Worker fails to pull a fresh snapshot -> USGS FDSN fallback attempted -> if both down, NO publish; the previous published surface stays live with is_stale set, watch_afad live_meta status='stale', lag/staleness alert pages. Customers get last-good-flagged scores, not an outage. Job retried with backoff; after N retries -> DLQ.
- _PARTIAL — some grid cells fail to score_ → Publish is atomic by construction: the worker builds a COMPLETE staging surface_table first, the integrity gate validates it, and only then does the single-UPDATE pointer swap occur. A partially built staging table is never pointed-to; it is quarantined and the run fails. No partial publish can reach serving.
- _DOMAIN integrity — model stops beating naive baselines_ → evaluate.skill_score vs Poisson/mean/persistence runs at publish time; if the new surface no longer beats baseline the pointer swap is BLOCKED, the prior published surface stays live, gate_report records the failure, and the integrity pager fires. A scientifically-regressed model can never auto-publish — this is the non-negotiable enforced in the data plane.
- _DOMAIN — post-mainshock staleness (scores stalest when most demanded)_ → Scheduler detects a large AFAD event and enqueues an incremental rescore of only event-affected cells/parcels; until it publishes, the published surface carries is_stale=true + stale_reason='post-mainshock', surfaced in /version, the API envelope, and the UI. Staleness is a visible monitored signal, not a hidden SLA miss.
- _Scheduler double-fire under replicas / leader death_ → Single scheduler machine + Postgres advisory leader-lock; pg_try_advisory_lock gates each tick so no double-fire even if mis-scaled. If the holder dies, the session-scoped lock is auto-released on connection drop and the next tick re-acquires. Explicitly NOT in-process APScheduler across API replicas. CI concurrency test asserts two schedulers -> one fire.
- _Cost runaway — autoscale storm on a flood of portfolio jobs_ → MAX_WORKERS hard cap bounds spend; queue-depth alarm pages before the cap; idempotency keys prevent duplicate work; DLQ stops poison-message retry loops; worker scales back to 0 after cooldown. Budget alerts on Fly/Cloudflare/Crunchy hit the same pager.
- _EMPTY — no work / idle period_ → Worker scales to 0 (cost zero); API stays at min 2 for HA; scheduler idle-loops cheaply. readyz still green because the published surface persists in Postgres independent of compute.
- _Secret missing or mid-rotation_ → readyz fails closed (503) so a machine missing a required secret is never added to the load balancer. Rotation = flyctl secrets set triggers a rolling restart; blue-green ensures no request hits a half-configured machine.
- _R2 outage (snapshots/tiles/exports)_ → Snapshot writes retried with backoff then DLQ; serving degrades gracefully — hazard scores come from Postgres, only PMTiles/exports are affected and Cloudflare cache serves last-good tiles. Alert raised; precompute defers until R2 recovers.
- _Managed Postgres failover_ → Connection pool retries on the new primary; readyz briefly 503s and machines drop from rotation until DB reachable, then rejoin. PITR + documented PostGIS restore runbook for data-loss scenarios. RTO is bounded by the managed provider SLA (open question vs contractual SLA).
- _Need to roll back SCIENCE without rolling back code (or vice versa)_ → The two axes are decoupled: code rollback = flyctl rollback (published pointer untouched, prices unchanged); science rollback = re-point risk_surface_publication.published to a previously retained surface_table (binary unchanged). Either is a single, audited, reversible operation.

**Tasarım kararları:**

- **One stamped, signed image with three process entrypoints (not separate images per process):** Single multi-stage Docker image; Fly process group selects api/worker/scheduler — Guarantees the code that backtests in evaluate.py is byte-identically the code that serves and precomputes — eliminating research/production drift, which is itself an integrity requirement. ### 6.9 — security-compliance

Security + compliance layer for EyeQuake's FastAPI modular-monolith + PostGIS stack on Fly.io EU/Frankfurt. Core stance: insurer portfolios and parcel addresses are KVKK/GDPR personal data (classification C3-Restricted), while the materialized hazard×site risk surface derived from AFAD is non-PII shared reference data — so tenant isolation, encryption, residency and audit controls concentrate on the PII plane, not the science plane. Enforcement is defense-in-depth and fail-closed: Cloudflare WAF/TLS at the edge, WorkOS SSO/SCIM + argon2id-hashed scoped per-tenant API keys for authn, PostgreSQL 16 Row-Level Security (DB-enforced via a non-superuser pooled role) PLUS an app-layer ownership guard for tenant isolation, envelope-encrypted address columns + crypto-shredding for erasure, and a hash-chained append-only audit_log mirrored to R2 Object Lock for tamper-evident underwriting/regulatory defensibility. Critically, the scientific-integrity layer is treated as a SECURITY control: a runtime Pydantic honesty-schema validator rejects any score payload missing model_version / AFAD provenance / uncertainty / baseline_comparison / 'tahmini' disclaimer, and a CI banned-claim linter blocks 'earthquake prediction / deprem tahmini / neural-net prediction / early warning' positive claims — because mis-selling a relative descriptive index as a prediction is an E&O/liability and regulatory exposure, not just an honesty lapse. Compliance is incremental-by-design: KVKK + GDPR (DPA, DSAR, residency, subprocessor governance) and SOC2-readiness controls are wired in as CI gates and data-model invariants from day one so a formal audit and reinsurer contracts are reachable without re-architecture by a 2-person team.

**Veri akışı:** Synchronous score path: insurer request → Cloudflare (TLS termination, WAF, bot/abuse filter) → FastAPI edge on Fly.io EU. If the input is an address (C3 personal data), it is geocoded by the self-hosted in-region geocoder (never leaving the region), producing a parcel/cell reference plus a geocode/resolution-confidence flag; low-confidence matches route to human-in-the-loop rather than silently scoring. The handler reads the C0 materialized parcel_risk_surface (shared, non-PII) — no tenant data crosses here. Response carries provenance + uncertainty + disclaimer headers/body. Async portfolio path: upload (encrypted on R2, short TTL) → pgmq job → batch worker as a SEPARATE process that re-establishes its own RLS tenant context, scores rows, writes a result file to R2 with server-side encryption + a TTL-limited signed URL; export volume is quota-checked and audited (exfil signal). Secrets/keys flow only from Fly.io encrypted secrets + KMS into process memory, never into repo, image, logs, or the audit body. **Failure mode'lar:**

- _RLS context not set (pooled connection reused, missing SET LOCAL, or worker forgets tenant context)_ → current_setting('app.current_tenant', true) returns NULL → policy denies all rows (fail-closed, never fail-open). FORCE ROW LEVEL SECURITY ensures even table owners are constrained.
- _API key compromised / leaked_ → Immediate revoke (set revoked_at) + rotate; only argon2id hashes stored so the secret itself never leaks from DB; anomaly detection flags usage from a new IP/geo or volume spike; audit trail reconstructs accessed resources for breach notification (KVKK/GDPR 72h).

- _Vendor outage or breach (WorkOS/Stripe/geocoder)_ → WorkOS down → cached session validity window / Clerk fallback for pilots; Stripe metering outage → buffer metering events in Postgres and reconcile against observability usage; vendor breach → subprocessor incident playbook + customer notification per DPA; least-data-to-vendor caps blast radius.
- _Multi-replica scheduler double-fires AFAD ingest/refit (duplicate writes, duplicate audit/meter rows)_ → Single dedicated scheduler process holding a Postgres advisory leader-lock (not in-process APScheduler); idempotency keys at extraction time; dedup-by-event-id (already in watch_afad/fetch_afad) prevents catalog corruption and duplicate billing/audit entries.
- _Injection attempt via address/geometry inputs into spatial SQL_ → All PostGIS access is parameterized via GeoAlchemy2 (ST_Contains/ST_DWithin with bound params, never string-built geometry); input validated by Pydantic; WAF filters obvious payloads; fuzz tests cover malicious address strings.

**Tasarım kararları:**

- **Where to enforce tenant isolation:** PostgreSQL RLS in the DB (non-superuser pooled role, FORCE RLS, fail-closed on missing GUC) PLUS an app-layer ownership guard — defense-in-depth, shared-schema + tenant_id by default — A 2-person team cannot rely on every code path remembering an isolation check; the DB becomes the last line so an app bug cannot leak a cross-tenant portfolio join. Shared schema keeps ops low; schema-per-tenant is reserved for large reinsurers that contractually demand it.
- **Scope of the protected (PII) plane:** Treat the AFAD-derived hazard×site risk surface as C0 non-PII shared data (no RLS/encryption); concentrate RLS, encryption, residency, and audit on C3 portfolios/addresses/building-cards — The science plane contains no personal data — protecting it like PII would add cost and complexity for nothing. Minimizing the C3 footprint shrinks breach blast radius and audit scope, which is exactly what eases KVKK/GDPR and SOC2.
- **Data residency + geocoding:** EU/Frankfurt default with a Turkey-region option on the roadmap; self-hosted in-region geocoder for C3 addresses, commercial geocoder only as a confidence-flagged fallback — Turkey is not in the EU adequacy list and Turkish insurers may demand in-country storage (VERBİS); keeping addresses in-region and out of arbitrary SaaS vendors is the cleanest way to satisfy both KVKK residency duties and GDPR cross-border rules without per-deal renegotiation.
- **Audit immutability vs right-to-erasure:** Hash-chained append-only audit_log + WORM R2 mirror, reconciled with erasure via per-tenant DEK crypto-shredding and redacted-but-chained audit records — Underwriting/regulatory defensibility needs tamper-evident history, but GDPR/KVKK erasure must still be honored across backups; crypto-shredding deletes the PII while preserving the audit chain and proving the erasure happened — satisfying both opposing requirements.
- **Status of the scientific-integrity layer:** Promote the honesty/baseline contract into SECURITY controls: runtime Pydantic validator (422 on missing provenance/uncertainty/baseline/'tahmini') + CI banned-claim linter + publish-time gate — Selling a relative descriptive index as a prediction, or shipping the 0.25° (~25km) grid as a 'parcel score', is an E&O/liability and regulatory exposure — a security/compliance failure, not just an honesty one. Gating at publish + CI + runtime makes it survive product and marketing pressure.
- **AuthN stack for two very different consumers:** WorkOS SSO/SAML + SCIM for the dashboard (Clerk fallback for early pilots); argon2id-hashed, scoped, rotatable per-tenant API keys (optional mTLS) for the machine API — Insurers/reinsurers require enterprise SSO/SCIM for procurement, while underwriting systems need stable machine credentials; splitting human vs machine authn matches both buyers without overbuilding, and Clerk keeps a pilot shippable before enterprise SSO is contractually required.

Derived, transformed scores are defensible; reselling the raw national catalog is the risky act, so it is explicitly gated.
- **SOC2 and pen-test timing:** Wire SOC2 controls as CI gates + data-model invariants + evidence automation from day one, but defer the formal Type II audit and schedule the first external pen-test pre-GA — A pre-revenue 2-person team can't carry full audit overhead, but reinsurer due-diligence will demand it; building controls as code now makes the eventual audit incremental rather than a rewrite, and pen-testing before charging for pricing-grade scores is non-negotiable.

### 6.10 — observability

Two-plane observability for the EyeQuake modular monolith on Fly.io EU. PLANE A (ops): OpenTelemetry as the single vendor-neutral instrumentation backbone -> OTel Collector fan-out to Grafana Cloud (Prometheus metrics, Loki logs, Tempo traces) + Sentry (errors/tracing), structlog JSON logs with trace-correlated context, RED metrics + multi-window multi-burn-rate SLO/error-budget alerting, Better Stack synthetic uptime + public status page. PLANE B (scientific/domain): an Integrity Sentinel job that turns EyeQuake's existing honesty machinery into live telemetry — AFAD feed lag/staleness (graduated from watch_afad live_meta), magnitude-of-completeness (Mc) and Gutenberg-Richter b-value drift (using the Shi&Bolt sigma already returned by b_value_aki), rolling baseline skill_score with bootstrap CI (evaluate.skill_score / bootstrap_mean_ci vs Poisson/mean/persistence), score-distribution drift (PSI), geocode-confidence distribution, batch success rates, and a post-mainshock staleness flag. The load-bearing inversion: observability is itself an integrity-enforcement mechanism — when a published model stops beating its naive baseline, when a served payload loses provenance/uncertainty/'tahmini' disclaimer (honesty-validator rejection), or when Mc rises above the completeness the live model was fit at, the system AUTO-FLAGS AND PAGES rather than silently serving. Durable integrity history lives in a Postgres model_eval table (audit-grade, queryable for model cards), mirrored to Prometheus only for alerting; an append-only immutable audit_log backs KVKK/actuarial defensibility. Telemetry is PII-minimized (parcel_ref + geocode_confidence, never raw addresses) to stay KVKK/GDPR-clean.

**Failure mode'lar:**

- _EMPTY — AFAD live feed returns zero events (quiet period, status='empty')_ → Do NOT alert as outage: empty-but-reachable is normal seismic quiet. feed_status{empty}=1 is informational. The alert signal is a FAILED fetch (WatchError -> eyequake_catalog_fetch_failures_total), not n_events==0. Dashboard distinguishes 'reachable+quiet' from 'fetch broken'.
- _ERROR — AFAD fetch fails / format change / outage_ → watch_afad raises WatchError; scheduler increments fetch_failures_total IMMEDIATELY and trips USGS FDSN fallback (fallback_active=true surfaced in /internal/integrity). Page on increase(fetch_failures_total[15m])>0 rather than waiting for lag to silently grow. live_meta stops updating -> staleness clock + dead-man heartbeat catch a wholly stuck scheduler.
- _PARTIAL — portfolio batch scores some rows, some fail_ → batch_rows_total{result=failed} increments; job marked status=partial; failed rows go to pgmq DLQ with idempotency keys; result file on R2 lists per-row status so the insurer sees exactly which parcels failed. Alert if partial_rate over threshold. Never silently emit a short portfolio.
- _SUCCESS-BUT-STALE — precompute is stalest right after a mainshock, exactly when demand peaks_ → post_mainshock_staleness_seconds is surfaced as an HONEST flag in API + UI (not hidden). Routes as informational while incremental rescore is within SLA; escalates to page only if rescore SLA (e.g. 15 min) is exceeded. Turns precompute's worst case into a monitored, disclosed signal.
- _DOMAIN — mainshock floods catalog: b-value drops, Mc rises transiently (real physics, busiest moment)_ → Separate seismic transient from model-validity breach. A labeled mainshock trigger (e.g. M>=6 in-region) opens a grace window: b/Mc drift alerts are suppressed-to-warn (expected aftershock physics, non-actionable at 3am) BUT the Mc-completeness invariant still pages if the SERVED model keeps scoring below the now-higher completeness, and a forced incremental rescore SLA starts. Avoids paging on earthquakes while still catching genuine invalidation.
- _INTEGRITY — published model stops beating Poisson/mean/persistence_ → min(baseline_skill_score_ci_low)<0 pages with severity=integrity and (per the locked stack) the publish gate blocks promoting that artifact; the previous compliant surface keeps serving (blue-green) so we degrade to a known-good model, never to a model that lost to a coin-flip baseline.
- _INTEGRITY — served payload missing provenance/uncertainty/baseline/'tahmini' disclaimer_ → Runtime honesty validator REJECTS the payload (envelope never reaches the customer), honesty_validator_rejections_total{reason} increments, Sentry issue + page. Treated as a Sev incident: the data plane attempted a dishonest score. The golden-parcel synthetic canary asserts the same four fields continuously as a black-box backstop.
- _MONITOR-THE-MONITOR — telemetry pipeline (Collector/Grafana/scheduler) silently dies_ → Dead-man switch: Integrity Sentinel writes telemetry_heartbeat_timestamp each run; absence > 30 min pages. Better Stack external synthetic is independent of internal telemetry, so a total internal blackout is still caught from outside.

### 6.11 — scientific-integrity

A cross-cutting enforcement plane that makes EyeQuake's honesty constraints mechanically unbypassable in production. It promotes today's three loose checks — run_pipeline.validate_outputs(), tests/test_web_honesty.py, and the docs/POSITIONING.md banned-word list — into FOUR defense-in-depth gates that all read ONE source of truth (a new src/eyequake/integrity module of code constants, not config): (1) a publish-time gate in the batch worker that refuses to promote a model unless it statistically beats the hardest naive baseline and carries full provenance; (2) a CI gate that runs validate_outputs + a negation-aware banned-claim linter + an envelope-contract test and blocks merge/deploy; (3) a runtime Pydantic v2 HonestyEnvelope on every score response_model that fails closed if disclaimer/provenance/uncertainty/baseline_comparison/score_version/resolution are missing; (4) a UI render guard that cannot draw a risk number without its uncertainty + provenance + baseline + 'NOT earthquake prediction' panel. Around these sit a versioned model registry + signed model cards, an immutable hash-chained per-score audit log, a content-hash byte-identical re-derivation path, an integrity & drift dashboard that pages on any invariant breach, and a public SSR methodology/Track-C-rejected site. The result: every score in API and UI ships with disclaimer + provenance + baseline comparison + version; banned positive claims cannot reach outward copy; Track C stays a Final='rejected' constant; and a skeptical insurer/regulator can independently reproduce any score and read its limits without trusting our word. Because src/eyequake is imported verbatim, the code that backtests in evaluate.py is the code that serves — no research/production drift to defend.

**Bileşenler:**

- **integrity invariant module (src/eyequake/integrity)** — Single source of truth for all honesty rules, as Python code constants NOT config: BANNED_CLAIMS regex set compiled from POSITIONING.md, REQUIRED_PROVENANCE_KEYS, REQUIRED_UNCERTAINTY_KEYS, REQUIRED_BASELINE_KEYS, DISCLAIMER_TOKEN='tahmini', canonical disclaimer strings, and TRACK_C_STATUS: Final = 'rejected'. Imported by the publish gate, CI linter, runtime validator and dashboard so there is exactly ONE list and no drift. Config cannot override any of it. _(Python 3.11 module with typing.Final / frozen dataclasses; depended on by FastAPI app, batch worker, CI, and Next.js (mirrored via generated TS const))_
- **HonestyEnvelope response model** — Mandatory wrapper for every score the API emits. Pydantic v2 model whose field/model validators reject any payload missing or empty in disclaimer.tahmini, provenance (model_version + content_hash + source=AFAD), uncertainty (bootstrap ci_lower/ci_upper), baseline_comparison (>=Poisson with beats flag), score_version, resolution (granularity + geocode_confidence); runs copy_linter over free-text fields. frozen + extra='forbid'; serialization fails closed. Attached as response_model on every score route so a naked score is structurally unserializable. _(FastAPI + Pydantic v2 (field_validator/model_validator), SQLAlchemy 2.0 read of materialized surface; global handler maps ValidationError -> 500 + Sentry page)_
- **model registry + signed model card store** — Authoritative record of which model_version is PUBLISHED and the immutable signed card behind it: content_hash, code_git_sha, catalog_snapshot_hash, per-baseline skill scores + bootstrap CIs, Mc, b-value, granularity, known limits, Track-C status. A row is immutable once status='published'; promotion only via the publish gate. Backs the provenance in every envelope and the public model-card page. _(PostgreSQL 16 tables (model_version, model_card, model_eval) via SQLAlchemy 2.0 + Alembic; card signed with a Fly secret-held key; rendered SSR by Next.js)_
- **publish gate (asset-check-as-gate)** — Promotes run_pipeline.validate_outputs() from a web-export check into a hard publish gate in the batch worker. integrity.publish_gate.assert_publishable(): recomputes evaluate.skill_score vs climatology/persistence/mean on a rolling out-of-time holdout, requires beating the HARDEST baseline with bootstrap_mean_ci lower bound > 0, requires complete provenance, and scans the model card with the banned-claim linter. On failure the artifact stays in staging and the live surface is untouched (degrade-not-outage). _(Python reusing src/eyequake.forecast.evaluate verbatim; batch worker process on Fly.io; writes model_version/model_eval; same function invoked by CI)_
- **negation-aware banned-claim linter** — integrity.copy_linter.scan(text)->[Violation]. Flags POSITIONING banned phrases ('deprem tahmini/öngörüsü', 'neural network ile tahmin', 'ne zaman/nerede/kaç büyüklüğünde deprem', 'erken uyarı sistemi') as POSITIVE claims, but ALLOWS them inside the honest-negation window ('...DEĞİLDİR', 'mümkün değil', 'reddedildi', 'Track C'). ## 7. Adversaryal bütünlük kritiği

**Integrity check:** PARTIAL / FAILS as specified. The four-gate defense-in-depth (CI linter + publish gate + runtime Pydantic validator + UI render guard) is sound in PRINCIPLE but does NOT survive end-to-end against the actual code, for three verified reasons. (1) The flagship invariant — 'score beats Poisson/mean/persistence, gated at publish, embedded in every response' — has no computational basis for the product actually sold: the served risk_index (export.py:82-92) is a global percentile RANK with no baseline forecast computed anywhere; the only skill number (71.1%) is a hardcoded single-split ETAS constant for a DIFFERENT model, explicitly flagged as supercritical/non-physical. A gate that requires a metric that is never computed is unenforceable; either the validator will reject every hazard payload (no baseline_comparison to supply) or it will pass a FABRICATED one. (2) The existing 'gate' (run_pipeline.validate_outputs) does only string/key presence checks and demonstrably PASSES a self-inconsistent surface today (meta.json min_mag=3.0 vs build_cell_index min_mag=4.0, never cross-validated; Mc/b-value completeness never invoked). Bottom line: the integrity gates can be made real, but as specified they enforce STRING presence and a NON-EXISTENT skill metric, so the deepest honesty risk (selling an uncalibrated relative rank as a baseline-beating, pricing-grade parcel score) passes straight through all four gates.

VERIFIED against code: the served score is build_cell_index().risk_index (export.py:82-92), a weighted percentile RANK of 6 signals. So the 'publish gate that requires beating the hardest baseline' has nothing to gate: a percentile rank cannot be scored against a Poisson baseline because it makes no count/probability claim. The entire 'observability-as-integrity-enforcement' edifice rests on a metric that does not exist for the product being sold. _Öneri:_ Before any of this architecture is real, Bora must define what 'beats baseline' MEANS for a relative percentile risk index — almost certainly a held-out spatial concentration / forecast-of-future-events test (does high-risk_index 2014-2019 concentrate 2020-2025 M>=4 events better than uniform/smoothed-seismicity-Poisson? a Molchan/ROC/gain-over-area test). - **[Reproducibility/content-hash key is unachievable as specified — risk_index is a global percentile rank, not a local function of one parcel]** _Neden:_ The design's flagship audit primitive is score_id = sha256(catalog_snapshot_hash | grid_params | site_inputs | building_card_version | model_version | parcel_ref) yielding byte-identical re-derivation per parcel. VERIFIED: risk_index uses .rank(pct=True) across the ENTIRE non-empty-cell population (export.py:76-92). A parcel's score therefore depends on EVERY other cell in the catalog snapshot, not just its own inputs. Adding/removing one event anywhere can shift a parcel's rank. So you cannot re-derive a single parcel's score from its own inputs + a snapshot hash without recomputing the whole national surface; the 'thin stateless read' and the per-parcel reproducibility key are in tension. Worse, the Stage-1 re-percentile in the scoring-engine layer makes site_hazard_index ALSO population-relative, so the same physical parcel's score changes every refit even with identical local seismicity. _Öneri:_ Accept that the score is a surface-level materialization, not a parcel-pure function: the reproducibility key must be (catalog_snapshot_hash, model_version, engine_constants_hash) -> the WHOLE published surface, and per-parcel re-derivation means 'point-in-polygon lookup into that immutable surface,' not 'recompute from parcel inputs.' Pin and store the full surface artifact per (snapshot, model_version) on R2 as the audit object. Separately decide and document whether a refit is allowed to silently re-rank an unchanged parcel (it will), because an insurer will notice a parcel's premium-driving score moving with no local seismic change — that is a product/actuarial trust bomb the design never addresses.

The honesty gate checks string presence ('tahmini' in disclaimer, source=='AFAD', required property KEYS exist) but checks ZERO numerical/scientific consistency. A surface built at M>=4 but labeled M>=3 (or below the ~2.5 completeness threshold the config itself warns about) sails through every gate. The seismology.magnitude_of_completeness / b_value_aki 'completeness gate' the design repeatedly invokes is NOT called by run_pipeline at all — it is dead w.r.t. the gate. _Öneri:_ Make validate_outputs actually scientific: assert meta.min_mag == the min_mag stamped into the surface artifact == a value >= computed Mc for the snapshot; assert cell_deg consistency; compute b_value_aki and fail if outside a plausible band; fail if any served cell's min_mag is below Mc. Add a regression test pinning the current 3.0-vs-4.0 mismatch as a BUG to fix, not a passing state. Re-derive Track-C status programmatically: a test that imports the deterministic R2 result and asserts it is ~0, so 'rejected' is a computed fact, not a comment that can rot when someone re-runs the model and gets a spuriously non-zero R2.
- **[No data-model migration / surface-versioning strategy for the percentile re-rank under incremental rescore — the 'incremental rescore only affected cells' graft is mathematically incompatible with global percentile ranking]** _Neden:_ Two grafts collide and the design never notices: (a) 'incremental rescore of only event-affected cells' after a mainshock, and (b) risk_index = rank(pct) over the whole population. A mainshock changes the rank of EVERY cell (the denominator/ordering shifts), not just affected cells. So 'rescore only affected cells' produces an internally inconsistent surface where rescored cells use the new population and untouched cells use the old ranks — the 0-100 scale no longer means 'percentile among all parcels.' The post-mainshock moment (highest demand, highest scrutiny) is exactly when this silently corrupts the score semantics. _Öneri:_ Pick one: either the score is absolute-per-cell (rate/intensity, locally recomputable, incrementally rescorable) OR it is a global rank (must be fully recomputed on any change, no true incremental rescore). The design wants both. For a percentile product, a mainshock requires a FULL surface republish, not an incremental one — size and SLA that full recompute (national grid is ~1886 cells today, cheap; but parcel-densified it is millions and the 'incremental' shortcut won't exist). - The risk_index is a population percentile rank, so a parcel's premium-driving score changes on every refit even with zero local seismic change (a rank can move because OTHER cells changed). No layer addresses how an insurer reconciles a moving score for an unchanged property, or how this interacts with the immutable-audit/reproducibility promise. This is a silent actuarial-trust failure.
- Mc/completeness is never enforced at serve or publish time despite seismology.magnitude_of_completeness existing — run_pipeline.validate_outputs does string checks only. A catalog or sub-region below completeness can be scored and sold; the 'completeness gate' is described in 4 layers but wired in zero.
- The 71.1% ETAS skill (national-pooled, single-split, explicitly flagged as supercritical/non-physical in etas_params.json and as single-split-noise in FINDINGS.md) is the only skill number in the system and is at constant risk of being surfaced as the hazard score's 'baseline_comparison' or marketed as the product's skill — the exact mis-attribution that creates liability. The API open-question even asks whether to expose the supercritical canonical ETAS at all.
- Building-vulnerability (BIS) — the stated CORE differentiator — has zero ground truth for Turkey, is an unvalidated expert taxonomy, and its outcome-validation against 2023 Kahramanmaraş damage data is gated on data access that may never come. The moat may be permanently self-reported-only, undermining the entire competitive thesis vs SeismicAI.
- Two-founder bus-factor against the FULL surface area (data eng + seismology + geospatial SaaS + RLS + billing + KVKK/GDPR + SOC2 + pen-test + on-call) is acknowledged but not mitigated to a survivable level — the Phase-1 scope alone (FastAPI+PostGIS+RLS+pgmq+scheduler+WorkOS+Stripe+OTel+honesty layer+geocoder) is unrealistic for two people pre-revenue and will force silent corner-cutting precisely on the integrity/security controls that are the differentiator.

No layer shows the actual deletion-across-all-stores cascade working under a backup restore.
- Single-source AFAD dependency: commercial license unconfirmed, schema-change contract test unimplemented, timezone unverified, magnitude-type unhomogenized — any one of these can corrupt or legally terminate the data feed the entire product is built on.
- Densification from 0.25deg to parcel is treated as a schema-absorbable Phase-2 step, but it changes the STATISTICAL VALIDITY of the score (per-unit event counts collapse, block-bootstrap may be invalid, percentile ranking over millions of sparse parcels is mostly noise). The design's own open question admits this; it is a model-validity cliff, not a schema migration.

**Verdict:** The design is architecturally competent and unusually self-aware about positioning, but its COMPLETENESS for full commercial production is overstated by a wide margin, and its central selling point — a scientific-integrity layer that mechanically survives into production — is partly a fiction when checked against the actual code. THREE findings are disqualifying until resolved: (1) the served risk_index is a population percentile RANK with NO baseline comparison, NO per-cell uncertainty, and NO skill metric computed anywhere — so the publish gate, the runtime baseline_comparison field, and the 'beats naive baseline' invariant that the ENTIRE design rests on have nothing real to enforce; the only skill number (71.1%) is a hardcoded single-split ETAS constant for a different, explicitly-non-physical model. (2) The current honesty gate (validate_outputs) is string-presence theater and would today pass a self-inconsistent surface (verified min_mag 3.0-vs-4.0 mismatch, completeness/Mc never checked). (3) ~90% of the production system (Postgres/PostGIS, RLS, billing, auth, API, integrity module, geocoder, observability) is greenfield, not a 'graft' onto the static-file prototype, so the effort/bus-factor for two founders is materially underestimated and the integrity/security controls are the most likely silent casualties of that crunch. Beyond those, the percentile-rank semantics break BOTH the per-parcel reproducibility key AND the incremental-rescore graft (a rank is global, not local); the product is sold to price premiums while the score is only ever validated to beat a coin flip (an E&O gap the lexical honesty layer cannot close); AFAD timezone/magnitude-type/commercial-license are unresolved blockers on a single-source dependency; and densification to parcel resolution is a model-validity cliff, not a schema migration. RECOMMENDATION: do not treat this as a buildable spec yet. First, Bora must DEFINE and IMPLEMENT a real skill metric for the relative hazard surface (spatial forecast-gain over smoothed-seismicity Poisson on a held-out future window) so the integrity gates have something true to enforce; build the integrity module and negation-aware linter as actual tested code; fix validate_outputs to assert numerical/scientific consistency (min_mag==Mc-safe, cell_deg, b-value band); resolve AFAD timezone/license as blocking pre-conditions; and re-scope Phase 1 to a single-tenant read-only hazard_zone API (lat/lon input, no geocoder, no billing) to make the founding-team effort survivable. The honest version of this product ships as relative triage intelligence with a real, computed, modest skill claim and a hard 'NOT FOR PREMIUM RATING' flag — which is exactly what the positioning doctrine demands and what the current architecture does not yet deliver.
